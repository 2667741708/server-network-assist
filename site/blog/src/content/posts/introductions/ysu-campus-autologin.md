连接了校园 Wi-Fi，电脑却仍然需要打开认证网页；原本已经登录，过一段时间又掉线。对需要长时间联网的电脑和实验室服务器来说，反复手动输入账号并不方便。

**这个项目的重点是让燕山大学校园网自动维持登录：登录成功后自动启动心跳，定期检查认证与联网状态，在确认异常后重新登录，并再次核实恢复结果。** 仓库名为 `ysunetlogin_openwrt`，现在也提供 Windows 桌面程序和 Python 命令行入口。

## OpenWrt 是什么意思？

OpenWrt 是主要用于路由器等网络设备的开源 Linux 操作系统。可以把它理解为“能安装软件、运行脚本的路由器系统”。普通路由器负责连接和转发网络，装有 OpenWrt 的兼容设备还可以在后台执行校园网认证与检查脚本。

在这个项目中，OpenWrt 是运行程序的一种环境：让路由器承担定期检查、必要时重新认证的工作。**如果你只想让自己的 Windows 电脑自动登录校园网，直接使用 Windows 版即可，不必刷路由器，也不必先学习 OpenWrt。**

## 自动维持登录，具体做了什么？

2026-10-24 更新后的源码默认在登录成功后自动启动心跳，无需另行启用，也无需设置开始和结束时间。心跳工作过程是：

1. 检查目标设备的联网状态，以及当前校园网账号和运营商。
2. 状态正常时保持连接；短暂异常先记录，达到配置的连续异常阈值后再处理。
3. 确认离线时，使用目标设备绑定的默认账号重新认证，再检查结果。
4. 当前账号或运营商与绑定配置不一致时，纠正会话。
5. 认证或 SSH 持续失败时逐步延长重试间隔，避免不断请求认证服务器。

如果外网能访问，但认证门户暂时无法识别账号，心跳会先保持现状，减少误断开正常连接的情况。这里的“心跳”就是周期性的状态检查。

自动维持登录依赖设备开机、程序运行和学校网络可用。它可以减少认证掉线后的手动操作，不能保证绝不掉线，也无法在学校停网或上游故障时凭空恢复网络。

## Windows 电脑如何开始？

只维护自己的电脑时，推荐先阅读 [Windows 本机使用与配置](https://github.com/2667741708/ysunetlogin_openwrt/blob/main/WINDOWS_LOCAL_SETUP.md)，再从 [项目 Releases](https://github.com/2667741708/ysunetlogin_openwrt/releases) 选择发布包。

1. 完整解压发布包，启动 `YSU-Netlogin-Healing-Manager.exe`。
2. 在“校园网账号”页保存账号、密码和已开通的运营商。
3. 在“一键连接”页选择“本机 Windows”，检查状态，再使用保存的账号连接。
4. 登录成功后，程序自动把本次账号绑定到该目标并开启应用内心跳，至此即已完成。
5. 需要查看记录或调整参数时，再进入“网络自愈心跳”页。可选的“随 Windows 登录启动（最小化）”用于重启后启动程序。

默认采用 **60 秒检查间隔、连续异常 2 次后重连**，普通用户无需设置。关闭桌面程序会停止应用内心跳；手动点击下线会同时停用该目标的心跳，避免刚下线就被自动登录。

本机使用不需要 SSH 或服务器；管理已经接入校园网的远端 Linux 主机时，才需要另外准备 SSH 和远端 Python 环境。Windows 保存的密码由当前用户的 DPAPI 加密，更换 Windows 用户后需要重新配置。

### 下载的 EXE 和最新源码可能不同

本文的自动启用行为对应 2026-10-24 更新后的源码与重建程序（2.2.0）。旧 2.1.4 EXE 不会自动获得新行为。运营商核验、网卡直连与心跳变化，应以 [更新说明](https://github.com/2667741708/ysunetlogin_openwrt/blob/main/RELEASE_NOTES.md) 为准；旧 EXE 需要重新构建才能包含这些源码变化。

## 命令行与 OpenWrt 路由器怎么选？

| 使用场景 | 建议入口 | 持续检测方式 |
| --- | --- | --- |
| 自己的 Windows 电脑 | 桌面程序，本机 Windows 目标 | 登录成功自动启用，保持程序运行 |
| 校内 Linux 服务器 | Python 命令行，或通过桌面程序 SSH 管理 | 命令行登录成功自动启动独立后台心跳 |
| 兼容的 OpenWrt 路由器 | Python 认证脚本配合 Shell 脚本 | 完整部署后登录，自动启动后台心跳 |

下载并完整解压源码后，可以先在脚本目录检查接入条件与当前状态：

```powershell
python netlogin.py campus-check
python netlogin.py current-status
```

需要主动扫描无线网络时，可运行 `python netlogin.py wifi-scan`。这条命令只扫描，不会切换 Wi-Fi。

命令行登录格式如下，占位内容需要换成自己的信息：

```text
python netlogin.py "学号" "校园网密码" 1
```

运营商编号为：`0` 校园网、`1` 中国移动、`2` 中国联通、`3` 中国电信。必须选择账号已开通的服务。**新版本中，这条命令登录成功后就会自动启动独立后台心跳，不需要手动开启。** 命令中的密码也可能留在终端历史中，个人电脑日常使用可优先选择桌面程序。

Windows 使用最新源码时，应完整保留相关模块，不要只替换 `netlogin.py`。具体环境依赖、网卡选择与配置示例见 [校园网直连使用说明](https://github.com/2667741708/ysunetlogin_openwrt/blob/main/CAMPUS_DIRECT_SETUP.md)。

OpenWrt 方案同样使用登录后自动启动的自愈心跳。旧版 `daemon.sh` 中的夜间暂停时段、cron 和失败重启逻辑已退出默认流程；现在无需设置重连时段，也不会因认证失败重启路由器。不同固件的 Python 和加密依赖可能不同，应完整保留源码模块，具体步骤见 [README 安装与配置](https://github.com/2667741708/ysunetlogin_openwrt#安装指南)。

### 退出 SSH 后还会自动重连吗？

直接在服务器上用新版命令行登录时，会启动独立后台进程；退出 SSH 或关闭终端后仍继续检查。重复登录会更新账号并复用进程。Windows 桌面端目前使用应用内心跳，需要程序保持运行。

后台心跳不等于安装开机服务：机器重启后，下一次成功登录会重新启动维护。需要主动下线时，直接执行：

```text
python netlogin.py logout
```

这会停止维护、删除保存的重连凭据并下线，不必先去关闭心跳。只想查看后台状态，可运行 `python netlogin.py heartbeat-status`；只停维护、保留当前会话用 `heartbeat-stop`。高级的一次性认证可追加 `--once`，日常使用无需这个参数。

Linux 凭据保存在当前用户私有目录，Windows 命令行使用当前用户 DPAPI 加密。后台进程参数和状态输出不包含密码。完整源码及自包含命令包的说明见 [命令安装文档](https://github.com/2667741708/ysunetlogin_openwrt/blob/main/CLI_INSTALL.md)。

## 为什么“认证成功”还要检查运营商？

根据仓库记录，2026 年 6 月学校认证流程已涉及 `auth1.ysu.edu.cn` 的 CAS 登录和后续 portal 服务选择。账号密码通过验证之后，还需要完成对应网络服务的登录。

因此，项目不仅提交账号密码，也会继续处理服务选择，并在新版源码中核对实际账号与运营商。指定服务找不到时会报错，不会悄悄改选其他服务。仅填写运营商编号也不会替账号开通服务。

## 连接没有恢复时，先看哪里？

- **检查校园网接入。** 能通过其他网络访问互联网，或仅能 SSH 到校内设备，不一定代表当前机器能访问学校认证环境。
- **检查账号与服务。** 密码有效、账号已开通目标运营商，是成功认证的前提。
- **检查代理直连规则。** 系统代理与 TUN 模式处理流量的方式不同；使用 TUN 时，仍可能需要把认证域名和校园网段设为直连。
- **检查心跳记录。** 确认目标、默认账号、检测开关和程序运行状态，再判断是认证问题还是上游网络问题。
