# 借网问题追踪规则

继承上级 AGENTS.md。本目录使用 traceable-development skill 的 REQ / ERR / OPS / ADR 编号体系。

1. 每个新问题记录触发条件、影响机器、现象、证据、根因、修复方案、实现位置、验证结果及回滚方式。
2. 严格区分：待排查、问题已确认、方案已确定、已实现、已部署、已验证。不能把方案记录当作修复完成。
3. 修改路由、代理、DNS、服务或维护任务后，同步更新需求、问题和验收记录，并关联现有代码，避免建立重复实现说明。
4. 无法核实的历史状态注明推断；未执行的测试注明未执行；未知代码行号使用 TODO-LINES。
5. 不保存账号密码、私钥、访问令牌或包含这些信息的完整配置。
6. 路由修复必须保护已有 SSH、跳板和管理隧道；自动维护、重启、退网恢复也必须验收。
7. 一次借网只允许一个方案控制公网出口。检查实际路由和策略规则，不能仅以 VPN 开关或服务 active 判断功能成功。
8. 新增记录使用本目录模板；更新 README 索引并补充对应需求和验收项。
9. 网络设计及变更必须遵守 [网络管理面板设计约束](网络管理面板设计约束.md)：校园直连与管理 WG 是并列路径，分别验收；保护内层地址、外层 Endpoint、回程和持久配置。
9. 网络变更必须遵守[设计约束：REQ-NET-002 校园互通](设计约束.md)：同一校园组网保持双向实际服务可达，覆盖借网/退网、代理/TUN、维护和重连；必须验证管理隧道内层网段与外层 Endpoint。不得把 cloud 跳板超时当作校园局域网互通失败。
