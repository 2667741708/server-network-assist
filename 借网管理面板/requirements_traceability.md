# 需求追踪

## REQ-NET-066：授权续期保留 WireGuard peer 并按套餐实际期限到期

同一设备、同一线路续租时沿用原 lease ID、WireGuard 公钥和地址。有限套餐可轮换授权令牌摘要并更新期限，旧令牌立即失效；租约到期严格采用套餐实际到期时间，不额外设置 30 天上限。无限期套餐使用不设到期时间的租约，令牌不做周期轮换；套餐、设备、客户或线路被明确撤销/停用时仍立即失效，中继 `offline_deadline` 继续作为控制面失联时的独立保护。

中继每轮对账先比较数据面配置。仅在配置发生变化，或读取到实际 WireGuard peer/客户路由缺失时，才写入对应状态；签名快照时间、令牌期限等授权元数据刷新只更新本地记录，不重设 peer、路由或流控。密钥/地址替换仍由明确的设备重置、密钥轮换或撤销流程触发。

有限授权 lease expiry 和月度订阅计划均使用套餐实际期限；不能用人为的 30 天上限截断套餐有效期。无限期套餐租约保持永不过期，不设置 30 天等期限上限，也无需周期续租；如收到续租请求，沿用并返回原 bearer token，不轮换 token、lease ID 或 WireGuard peer。明确撤销仍立即生效，relay `offline_deadline` 独立用于控制面失联保护。C201 已将 67 个启用套餐的 `lease_seconds` 迁为套餐实际期限；纠正原 30 天截断后，一个 3650 天套餐从 2,592,000 秒改为 315,360,000 秒。另有 1 个符合条件的无限期活动租约迁为永不过期，且 token、peer 和计数器保持不变。活动控制服务重启成功。D321 较早一次 `source-physical` 连接曾通过公网探针；更新后的后续重验未完成 WireGuard 握手，当前已回滚到 IDLE，不能据早先成功认定当前连接可用。relay 侧握手和计数器增量仍待独立复核。见 TEST-NET-072/073 及 `handoffs/2026-10-02-WireGuard稳定peer续租与替换模拟.md`。

## REQ-NET-065：本机（whm-save）使用最新校园直连客户端并以源服务器 IP 订阅

用户要求："给我本机使用最新的校园网直连客户端。并使用源服务器ip地址订阅。使用新版本。"

**要求**：① 本机客户端升级到最新的 `campus-ip-direct` 变体（`0.1.62`），旧版本目录保留为回滚点；② 订阅的 `provider` 必须是**源服务器 IP**（`10.20.32.13`）而非域名入口；③ 注册后必须真的入网并逐层验收，不得以"已连接"的状态字段代替出口证据。

**实现**：

- 客户端：`0.1.53-473e429b5a6f` → `0.1.62-campus-ip-direct`，8 个文件逐一 sha256 对照 `build.json`（`sha256`/`service_sha256`/`cli_sha256`），服务注册项改指新目录；旧目录原样保留。换版脚本的两个缺陷见 ERR-NET-042。
- 订阅：用户用管理员密码在**修复后的面板**签发 `base_url = http://10.20.32.13:9182` 的地址（顺带完成 REQ-NET-063 的手验），本机以 `LanBridgeCLI.exe subscription-add --file <临时文件>` 注册 —— CLI 明确要求令牌**不走 argv**，临时文件注册后即删。随后 `subscription-select --confirm` → `refresh` → `connect`。
- 新订阅 `provider = 10.20.32.13`，原 `whm12.art` 两条订阅**保留未删**，可随时切回。

**验收（2026-09-30，已入网）**：

| 层面 | 证据 |
|---|---|
| 路由 | `route-preview`：`control_host=10.20.32.13`、入口 `10.20.32.13:51910`、`status=default_route`、**`ambiguous:false`** |
| 连接计划 | `access=campus-source-wireguard`、`egress=source-physical`、`capture=kernel-route`、`authorized=true`、`protected_endpoints=["10.20.32.13:51910"]` |
| 源链路选择 | `source_link_probe`：选中 WLAN（`id=6`），`selection_reason=source_probe`，`status=confirmed` |
| 状态 | `connected=true`、`state=CONNECTED`、隧道 `pnxc7a5cf21b93d`、授权 `grant_0b0b…`（配额 10 GiB） |
| 出口（逐层，非推断） | `probes.egress_verified=true`，每条结果 `via=pnxc7a5cf21b93d`（隧道网卡）；百度/QQ/阿里/gstatic/微软 通过；真实下载 36.64 MB 成功 |

**边界（设计如此，不是缺陷）**：`egress=source-physical` + 校园直连 ⇒ **境外站点不可达**。探针实证 wikipedia / chatgpt 超时的原因是 `校园网卡 … 直连 … 失败：timed out`。不得据此报缺陷，也不应"修"。

**未验证**：客户端 `usage` 计量在下载 36.6 MB 后仍为 `rx=0 tx=0 used=0`，且无上报事件 —— 见 [OPS-NET-064](handoffs/2026-09-30-订阅地址弹窗不可见与地址导出.md) §10 的待观察项。不得宣称计量正常。

## REQ-NET-064：明文 HTTP 入口下的「复制地址」必须真的可用

用户上线后手验反馈：弹窗可见、`.txt` 可下载，但「复制地址」复制不进剪贴板。这是 REQ-NET-063 的必然延伸 —— "能看到地址"必须包含"能把地址拿走"，否则用户仍只能靠手动框选。

**要求**：地址弹窗的「复制地址」按钮在**所有管理入口**上都必须真正写入剪贴板，包括明文 HTTP 的校园入口（`http://10.20.32.13:9182`）与 WireGuard 入口（`http://10.201.250.1:9180`）—— 这两者**不是安全上下文**，`navigator.clipboard` 为 `undefined`。复制失败时必须给出真实结果提示，并保留"地址已选中、可手动 Ctrl+C"的退路。

**实现**：`navigator.clipboard` 可用时优先使用；不可用或被拒时回落到 `<textarea>` + `document.execCommand('copy')`。见 ERR-NET-043。

**验收（2026-09-30，已上线）**：

- 离线夹具：`tests/subscription_admin_ui_browser.cjs` 运行在 `http://admin-fixture.test`（**非安全上下文**，与 9182/9180 同条件），先断言 `isSecureContext === false`、`typeof navigator.clipboard === 'undefined'`，再监听浏览器真实 `copy` 事件比对完整地址；变异验证确认还原为无兜底逻辑时断言变红。
- 线上实机：`tools/admin-copy-live-check/` 对三个生产入口实测，全部把 472 字符合成地址完整写入剪贴板；安全上下文在无权限时走 `writeText → NotAllowedError → execCommand` 兜底链成功，授权后走主路径且操作系统剪贴板回读一致。
- 发布：按 ADR-0002 完成并做双向回滚演练，见 [OPS-NET-064](handoffs/2026-09-30-订阅地址弹窗不可见与地址导出.md) §9.1。

## REQ-NET-063：订阅地址可见性与单地址 txt 导出

用户要求"生成地址后要能看到具体地址"并"允许生成对应的 txt 文件"。

**可见性**：`#address-dialog` / `#reauth-dialog` 从 Tabler 的 `modal modal-blur` 类改为项目自有 `address-dialog` 类。原类名触发 Tabler 作者样式的 `.modal{display:none}`，它优先于浏览器给 `dialog[open]` 的 UA 样式，导致 `showModal()` 后弹窗计算样式为 `display:none`、矩形 0×0（见 ERR-NET-041）。同一次修复还补上了重认证后**重放结果被丢弃**的缺陷：`onResult` 回调现在沿 `run()` → `request()` → `pendingRetry` → `submitReauth()` 传递，重放成功后把服务端返回的地址真正显示出来。

**txt 导出**：地址弹窗新增「下载 .txt」按钮，复用既有 `downloadText()`，文件名为 `订阅地址-<客户编号>.txt`，内容为该条完整地址（含 450+ 字符的 `#enroll=` 令牌，不以省略号截断）。批量签发的「复制全部地址（文本）」与「导出结果 CSV」保持不变。

**窄屏**：「补发开户入口」的内联 `width:22rem` 改为 `.reissue-field` 响应式规则，390px 下页面不再水平溢出（`scrollWidth` 427 → ≤390）。

**验收**：`tests/subscription_admin_ui_browser.cjs` 已按 v2 真实 ID/行为整体改写，新增弹窗可见性、txt 导出内容、重认证重放三组断言，并**以变异体反证**：三组断言在对应"修复前"变异体上全部变红（详见 ERR-NET-041 表）。线上部署与用户手验见 [OPS-NET-064](handoffs/2026-09-30-订阅地址弹窗不可见与地址导出.md) / TEST-NET-070 / ADR-0002。

## REQ-NET-059：订阅地址生命周期（查看 / 补发 / 销毁 / 延长）

## REQ-NET-058：登录持久会话与集中式重认证

登录页提供"保持登录（30 天）"勾选（`remember: 30`，服务端既有契约接受 0/7/30；不勾选为 8 小时），**不存储密码**，仅延长 Cookie 会话。管理面板的请求层做集中重认证：401 或管理员验证过期的 `fresh()` **403**（该响应码为 403 而非 401，此前是"每次签发都要退出重登"的直接原因）→ 弹出单次重认证对话框（不堆叠）→ 用新 CSRF **重放一次**；CSRF 失效的 403 走整页刷新，绝不循环；同时移除各操作表单原有的"确认密码"字段与逐操作确认块。`fresh()` 文案修正为"请重新验证管理员密码（验证有效期 5 分钟）"，不再指向错误的设置页。隔离环境验证 remember=30 登录；**线上真实交互登录未验证**（需管理员凭据）。见 [OPS-NET-063](handoffs/2026-09-30-订阅管理控制台v2上线.md) / TEST-NET-068 / TEST-NET-069 / ADR-0002。
