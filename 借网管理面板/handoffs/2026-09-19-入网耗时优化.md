2026-09-19。REQ-NET-055 / ERR-NET-038 / TEST-NET-066。目标客户端 0.1.19。

## 已确认的现场条件

用户确认 0.1.18 在校园 Wi-Fi、校园网运营商认证在线时，可以通过校园私网连接 C201-4090，并使用源机代理出口。只读 API 同样显示已入网。此前 OPS-NET-060 的热点/idle 状态是恢复核验时的历史状态；旧版 0.1.16 的绑定错误不是当前连接状态。

## 耗时证据

后台相关任务日志中的最近四次入网分别为 70,965、53,722、49,367、146,418 毫秒。订阅与租约 API 仅约 44–125 毫秒。日志中四次接入快照各约 2.3–4.2 秒，重复全量网络查询、独立 DNS/IPv6 配置、完整网站检测等待约 11–16 秒；最慢记录 health 中 inspect 单次 53,488 毫秒，整个 health 71,925 毫秒。阶段存在嵌套，不可将所有计时直接相加。

源服务器 relay.timer 的 OnUnitActiveSec=10s、AccuracySec=5s；首次 peer 应用和 WireGuard 握手重试仍可能产生额外等待。本轮只读查看，不调整该 root 定时器、不重启源机隧道或代理。

## 0.1.19 改动

- 初始网络基线只读取需要的路由、网卡和管理隧道外层端点，省去未被连接逻辑使用的全量 DNS/防火墙快照。复用已验证的接入快照用于审计记录；认证后、保护后仍读取真实网卡并验证接入未改变。
- 合并 DNS、IPv6 保护和首次隧道网卡信息到单次 Windows helper 调用；合并健康校验中的路由/DNS 核验与网卡信息，避免再读全量 inspect。同一校验中 NRPT、路由各查询一次，仍逐条核对实际配置。
- 入网关键路径预计 PowerShell 调用由 13 次减到 8 次。此为代码调用数，不是完整启动实测加速倍数。
- 最多三路并发真实绑定隧道的公网 HTTPS 检测，首个目标可达后继续健康/所有权校验。校园网页或本机 Clash 成功不替代源隧道公网验证。未完成的国内、国外、校园和本机代理详细检测在已连接监测中补齐；全部公网失败仍撤销自有配置、恢复原出口。
- 连接或恢复期间推迟可选的校园流量/CAS 后台查询，避免竞争；慢启动接近租约到期时先续租并核对合同，再报告成功。优先取消与恢复入口保持可用。

## 核验范围与制品

新增回归覆盖快速验证不等待慢尾部、路径绑定、国外回退、全部失败、后台完整补测、慢启动租约续期、合并配置、路由/DNS 变化拒绝。完整离线验收结果以 artifacts/code-acceptance.json 为准；最终冻结制品以 artifacts/dist/{build,verification,source-manifest}.json 为准。

本机只读基准中，生产查询主体 full 3,823ms、lightweight 158ms（同一进程顺序运行，存在缓存/顺序影响；只排除需要管理员权限的 WG 外层端点读取，不能作为完整入网倍数）。在当前源代理隧道上，新的快速公网 HTTPS 验证 163ms、百度 HTTP200。network_mutations=0；此数值不含建立隧道、路由配置、健康检查。

证据：artifacts/connection-performance-before-019.json、connection-readonly-benchmark-019.json；tests/test_connection_performance.py、tests/connection_batch.ps1。源服务器根定时器等待尚未优化；不承诺固定入网秒数。

离线包继续包含 Python/库、WireGuard、WebView2 与 VC Runtime，不要求额外下载。安装新版到独立版本目录并更新快捷方式；保留当前运行中的旧版连接，下一次正常退出并重开后使用新版。
