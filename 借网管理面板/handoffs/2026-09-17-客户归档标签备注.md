# OPS-NET-033：客户归档、回收站、标签与备注

- 状态：已部署及验证；关联 REQ-NET-032 / TEST-NET-040。
- 范围：商业控制后台、订阅管理 UI 和管理员 CLI；没有替用户处理真实客户。

## 问题与方案

已有停用客户仍堆积在日常表格，缺少分类、备注和可恢复清理流程。加入管理员专用 commercial_customer_metadata 表，默认原客户为 active，保存标签、备注与 active/archived/deleted 分类。删除使用可恢复回收站，不物理删除账务、地址或身份。

归档/回收站变更与停用客户、撤销租约、版本历史在同一事务完成；仅编辑标签/备注保留服务和租约。恢复分类保持服务停用，必须再次明确启用。复用原服务变更 API、近期凭据确认、CSRF、版本与完整 revision 冲突保护；数据库 trigger 阻止旧代码绕过分类直接启用，兼容 API 给出可读错误。其他客户不受影响。

UI 默认日常客户，增加已归档/回收站/全部与标签筛选，备注支持完整展开阅读并参与搜索；行内“标签 / 备注 / 归档”在当前视口打开编辑窗口。确认区明确显示停用、撤销和恢复语义。客户端订阅 DTO 不包含管理员标签或备注。

## 验证证据

81 项相关后台测试通过：含活跃租约期间备注修改、归档/回收站撤销、禁止直接启用、恢复不自动启用、原 URL/身份/用量保留、输入边界、冲突与其他客户隔离，以及真实应用测试服务器上的认证/CSRF/兼容启用接口保护。两套拦截请求的浏览器 fixture 通过：标签筛选、完整备注和 HTML 文本安全显示、归档隐藏、回收站、恢复、凭据清空及既有订阅/出口工作流，1440/1024/390 无整页水平溢出。

4090 候选运行时在独立临时数据库验证标签、归档、回收站、恢复和原订阅/用量保留通过；未修改线上客户。源端部署仅重启用户商业控制 API sna-commercial.service；路由、ip rule、Mihomo、商业 WireGuard 和中继 timer 指纹保持，原地址与设备摘要保持。备份 `/home/a/sna-customers-20260917/backup-1789652585368627535`。root 管理员 CLI 两模块同步，无中继重启，备份 `/home/a/sna-customers-20260917/cli-backup-1789652609696048311`。

真实公开 HTTPS 入口登录、匿名401、Cookie/CSRF、12客户的新字段和 CLI 字段一致、九份公开资产一致均通过。线上只读验证，没有归档、删除或编辑真实客户。没有操作员本机网络测试。

## 回滚与限制

恢复备份模块和静态文件，仅重启商业控制 API；保留新增 metadata 表和保护 trigger，不能用旧 SQLite 快照覆盖持续计量。回收站不是永久擦除；恢复不续期、不恢复已撤销租约、不清零流量，需要服务有效后客户端重新入网。中继按现有同步周期落实撤销，不能宣称点击后所有数据包瞬间消失。汇总消费仍包括历史归档/回收站客户，列表按分类筛选。
