# ERR-NET-016 / OPS-NET-016：一键入网与未认证 Wi-Fi 私网限制

- 日期：2026-09-17。
- 状态：一键流程已实现、隔离验证及只复制安装完成；未认证 Wi-Fi 网络限制待进一步实际验证。
- 影响平台、机器及范围：用户 Windows 校园 WLAN、4090 商业源网控制服务与客户 GUI。
- 关联：REQ-NET-016、TEST-NET-024；明确更新 REQ-NET-007/009/015 的手动启动行为，保留 REQ-NET-003/004 和校园互通保护。

## 触发条件和现象

用户要求点击开始入网直接执行：个人账号在线时自动 Logout 再入网，不再要求独立 Logout 或第二个确认。随后用户提供已成功 Logout 的截图，订阅刷新报 TLS 握手失败，并报告 10.20.32.13 连续 ping 超时，重新校园认证后 ping 恢复。

## 真实证据

用户截图证明旧版手动 Logout 返回已确认下线，随后订阅不能读取；用户终端输出记录两轮全超时和之后 2ms 回复。没有同步 TCP 9182 或 UDP 51910 的注销前后对照，因此不能仅据 ICMP 将所有未认证校园 Wi-Fi 判为不支持，更不能推定有线一定支持。

本轮本机只读探测在 03:07:37 UTC：WLAN 10.126.63.249，绑定物理接口到 10.20.32.13:9182 TCP 可达；匿名公网订阅 GET 在默认和客户端 TLS 上下文均为 401。此时可达性不能代表用户截图中注销后的状态，也不能证明实际借网。本轮没有注销、登录、切换网络或执行连接测试。

## 根因

已确认：旧版本个人账号在线直接拒绝入网，主按钮还有额外确认，反复点击不会改变门槛。截图的 Logout 已成功，而订阅刷新失败属于后续路径问题。

推断：无线未认证状态可能限制跨校园网段访问或公网订阅入口，因此没有可用的源网控制/数据路径；也未排除 ICMP 单独被过滤、短暂网络变化或公网 API 不可达。此前只有认证在线时私网可达的核验，不能推出“连接 Wi-Fi 即可借网”，需要更正验收边界。公私钥不能使被校园访问控制封锁的 TCP/UDP 路径变得可达。

## 修复方案与实施记录

`client_ui/client.js` 去掉开始入网的第二次确认；pendingAction 在请求前设置并禁用按钮，重复点击不发新请求。保留独立 Logout 的确认，不增加显眼说明。订阅瞬时离线时保留上次节点和套餐展示，并标记保留上次数据；授权获取失败仍禁用入网，防止将缓存当成有效授权。

`client.py` 的 online_connect：验证校园物理接入和订阅入口，个人 online 时获取当前签名授权并校验选定节点，检查已部署源网 TCP 9182 后调用既有 auth1 当前会话 Logout。必须成功、复核 offline 且物理网络不变，再次探测源网 TCP，才签发租约/安装隧道。个人已 offline 不注销；状态未知、授权无效、源网预检查失败时不注销。注销后 TCP 失败明确报告“Logout 后校园私网源网不可达”，不建隧道。租约/安装失败走既有回退，并明确个人账号已下线，不声称恢复了个人校园认证。

真实连接仍以近期 WireGuard 握手为准，TCP 不代替 UDP 验收。不自动登录个人账号、不更改校园 ACL、不切换 Wi-Fi、不借由管理 WG 假冒校园路径。接入报告允许 online 显示可点击开始并提示自动 Logout，检查本身无网络写操作。原生启动提示缩短并区分一键新版；修订标记 20260917-one-click-connect。

本次用户授权是在其主动点击开始入网时执行 Logout，属于产品行为授权；没有扩大为工具可主动注销/借网或终止本机旧客户端的授权。

## 风险与回滚

用户主动开始入网可能注销个人账号，但若未认证 Wi-Fi 随后阻止源网访问，就不能入网；不能自动恢复个人登录。客户端明确报错并保留物理连接。可在用户手动 Logout 后用 PowerShell `Test-NetConnection 10.20.32.13 -Port 9182` 验证真实控制路径；只有无需个人认证且实际可达控制和 WireGuard 数据端口的接入才适用。不能保证所有有线接入满足。

原 gui-6e986c803840 手动 Logout 版制品仍保留，回退只修改桌面目标，不删除配置或私钥。不得用数据库或旧令牌回滚覆盖已注册客户。
