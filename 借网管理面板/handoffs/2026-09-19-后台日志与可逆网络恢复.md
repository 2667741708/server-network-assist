# OPS-NET-060：后台日志与可逆网络恢复

日期：2026-09-19。REQ-NET-053 / REQ-NET-054 / ERR-NET-036 / ERR-NET-037 / TEST-NET-065。

## 用户最新约定

用户要求借网失败时恢复原网络、路由改动始终可逆、即使客户端忙碌也可主动恢复。本轮明确替代旧版“失败后持续阻断公网、等待手动恢复”的策略：连接失败、监测失败、网络接入改变或进程异常退出，自动撤销澜桥自己的配置；不自动重新入网。不切换运营商，不启动新的真实借网测试。

恢复原出口可能继续使用用户原校园/热点套餐；不保证上游离线、第三方代理节点不可用或站点拒绝时仍能上网。

## 客户端 0.1.18

- Session 失败分支自动退出/恢复；stop、restore、release 独立执行，单项失败不跳过剩余清理。失败保留 recovering、所有权记录和详细日志；监测重试待完成清理，不重新申请隧道。
- 原默认网关不删除、不改写；校园路由只添加有记录的 ActiveStore 条目，按目的前缀/接口/下一跳/metric 精确撤销。WireGuard 客户专用服务须校验所有权，卸载后核对服务消失且客户隧道路由消失，才能删除恢复记录。
- NRPT 和防火墙逐项恢复，保存剩余工作，核对实际残留；查询路由报错不能伪装为没有路由。用户改过的 DNS、Clash、WinINET 字段保持原样，不按旧快照覆盖；第三方 VPN、管理隧道保留。
- 恢复接口 /api/recovery 在正常操作 busy 时仍可接受，保留 Origin/令牌校验。取消后续连接阶段，恢复任务优先，重复请求返回同一任务，旧操作不能覆盖恢复结果。
- 页面常驻小型“恢复原网络”按钮，不因普通操作 busy 禁用；桌面/开始菜单“澜桥-恢复原网络”快捷方式执行 --disconnect，无需订阅或互联网。客户端在运行时通过私有回环接口请求恢复；没有运行时离线恢复所有权记录，完成/失败显示结果。
- 独立 guard 在进程退出后取得全局互斥锁，复核 owner 防止清理新实例，再恢复原网络；启动新客户端先清理旧记录。UI session 文件写入失败不会阻断退出；隧道、路由、代理各自恢复记录必须在改动前持久化。
- 有损坏的恢复记录时拒绝凭猜测删除陌生网络，但仍尝试其他独立且有效的记录；记录保留，不谎报恢复完成。

## 后台日志

客户端连接详情 → 运行诊断 → 打开后台日志。日志位于当前 Windows 用户对应的 C:/ProgramData/PureCampusNext/<SID>/logs；UTC 时间、PID/线程、任务相关编号、阶段耗时、异常链/errno/winerror、DNS/绑定 TCP/握手、各网站检测和清理结果以 JSONL 保存。每次运行独立文件，2MiB×4滚动，最多5组约40MiB；密码、令牌、私钥、认证头、Cookie、链接凭据脱敏，日志失败不阻断主功能。

源控制服务已窄部署日志：/home/a/.local/share/server-network-assist-commercial/data/logs。记录 HTTP 状态/拒绝原因、写入类客户操作和每30秒只读采集 Mihomo/WireGuard/root relay 服务状态/近期日志。只重启用户控制服务，未重启 WG/Mihomo，不改变客户策略。root relay 命令埋点在源码已完成，因 root 目录不可写未部署该埋点；线上由只读采集覆盖运行信息。
