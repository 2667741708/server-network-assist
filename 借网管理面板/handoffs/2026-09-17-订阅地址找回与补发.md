# OPS-NET-014 / ERR-NET-014：订阅地址找回与补发

- 日期：2026-09-17。
- 状态：已实现、已部署，隔离测试及实际管理入口读取已验证。
- 范围：4090 商业源网管理 API/SQLite 与订阅静态页。
- 关联：REQ-NET-014、TEST-NET-022；继承 REQ-NET-002/003/004/013。

## 触发条件和现象

用户未保存生成地址后无法在已开户客户列表找回，要求地址可再次查看。

## 真实证据

4090 enrollment_tokens 原有表只有摘要及客户/时间，没有可还原令牌；原结果仅存在网页内存。服务已有 Fernet vault 密钥。部署前有 10 个客户、7 个设备和有效租约。摘要不能逆向恢复，不伪造历史地址。

## 根因

摘要验证与管理员找回地址是不同需求，原实现只有单向验证及一次性返回值，没有受保护的存档。

## 修复方案与实施记录

`subscription_archive.py` 使用既有 cipher 加密 URL 入 subscription_addresses；列表只返回状态，查看/补发经既有 client-service/action 的认证、CSRF、fresh 验证及 no-store。审计不记录令牌。`client_store.py` 月度开户事务增加存档回调，失败整体回滚；原 CLI 调用兼容。管理 UI 增加客户行查看/补发及再次输入凭据的确认表单，显示未留存/已使用/过期/设备上限；不使用浏览器持久化存储，退出清空。

补发沿用原客户、套餐、授权、账期及设备，不续期，旧未使用令牌失效，新 24 小时单次令牌加密保存。客户/套餐停用、设备满额或无有效源网授权时拒绝。

`scripts/deploy_subscription_archive.py` 分 prepare → 候选测试 → apply，按远端基线哈希制作窄补丁，不发布其他 WIP。仅重启 user sna-commercial 管理 API，不操作 WireGuard/客户端网络服务或 cloud Caddy。文件及一致数据库备份：`/home/a/.local/share/sna-subscription-archive-20260917/backup-1789611969275458533`；目录 0700、数据库 0600。

## 验证结果

TEST-NET-022 的 Python、远端候选及隔离 UI 测试通过。真实 WG 管理路径的认证、元数据及查看操作通过；公网更新页面 200。旧客户/套餐/授权/账期/令牌逐行与备份一致；当时 4 个旧客户符合补发条件，未执行真实补发。部署前后校园 IPv4 路由摘要、wg-quick@sna-commercial 与 server-network-assist-client-1000 的状态/InvocationID/MainPID 一致。

## 风险与回滚

数据库与既有 vault 密钥须一起保留，否则地址无法解密。已使用地址可查看但不可重复开户；历史摘要客户仅在尚有设备额度且授权有效时可补发。重启管理 API 清空近期验证时间，表单再次登录即可。

回滚仅恢复该备份的代码和三个静态文件，再重启管理 API；不覆盖恢复运行中的 SQLite，避免抹掉后续租约/开户。新增表可保留。回滚前核对后续改动，不能覆盖其他变更。
