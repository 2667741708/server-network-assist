# OPS-NET-031：订阅数据仪表盘与原址服务变更

- 日期：2026-09-17。
- 状态：已实现、已部署，隔离修改和真实鉴权读取已验证。
- 范围：4090 商业控制 API、CLI、SQLite additive 审计表、订阅管理静态页面、cloud Caddy 窄路径代理。
- 关联：REQ-NET-030 / TEST-NET-038，继承校园互通、管理隧道与操作员本机网络不修改约束。

## 触发条件和现象

原管理列表缺少统一的客户权限、额度、消耗、期限和状态视图；管理员需要保留同一订阅地址，逐客户升级服务。

## 真实证据

4090 已部署源 API 的真实管理员会话读取 12 个客户，当时 10 个授权可入网、2 个有效租约。今日和累计为实际服务端计量数据；不是公网探测证明。没有用真实客户的授权/额度作破坏性测试。

## 根因

原接口分别提供客户、授权、租约及用量，缺少一致快照、跨字段事务编辑、版本冲突检查和按客户独立套餐变更。

## 修复方案与实施记录

新增 `subscription_dashboard.py` 聚合快照、逐租约累计计数 LAG 差量、用户方向速率、账期/历史与可用性；事务修改客户、独立克隆套餐、授权期限和出口，保留原 enrollment 摘要/URL 密文/设备。服务版本与授权 fingerprint 拒绝并发过期变更。出口切换或停用撤销旧租约，提高额度/续期保留用量和原账期。未兑换已存档地址可显式原址恢复 24 小时，已兑换不重置。

新增 GET dashboard 与 POST subscription-update，使用既有认证、CSRF、fresh 管理员验证和 no-store。CLI 增加 subscription show/update。UI 复用已部署订阅页的 section/grid/form/table，增加搜索、筛选、汇总、可滚动完整表格、逐客户编辑、设备停用、历史记录及无令牌 CSV。刷新失败不允许使用旧快照修改，退出清空，凭据不做浏览器持久化。

`scripts/deploy_subscription_dashboard.py` 按 prepare → 候选隔离验证 → apply 制作商业 GET/POST 窄补丁，保留源端其他 API。仅重启 user sna-commercial 控制服务，未重启客户端、WireGuard、Mihomo 或中继。源端备份 `/home/a/sna-dashboard-20260917/backup-1789641985638753166`；数据库一致备份 0600，目录 0700。root CLI 只更新两个模块，无中继重启，备份 `cli-backup-1789642064815026582`。cloud Caddy 校验后 graceful reload，备份 `/etc/caddy/Caddyfile.sna-subscriptions-1789642014241568256`。

## 验证结果

联合后台回归总计 69 项通过。后续仅静态增强加宽桌面视图、固定客户首列和行内查看地址入口；两套浏览器用例再次通过，没有新增 API/网络变更。无服务重启静态备份：`/home/a/sna-dashboard-20260917/dashboard-style-original.css` 与 `dashboard-asset-original-dashboard.js`。公网三份 HTML/JS/CSS 字节与发布文件一致，root CLI show 可读取 12 客户。

TEST-NET-038：本地相关后台回归、两份隔离浏览器用例和 4090 候选真实 Python/依赖下的临时数据库检查通过。候选确认 URL/消费/共享套餐不变、180 天/无限量、过期后既有设备继续入网、代理门禁、切换撤销及并发拒绝。浏览器点击表单验证期权限与额度载荷、390px 横向滚动、长名称换行、刷新失败锁定和退出清空，所有请求 fixture 拦截，截图不是真实客户。

真实 4090 匿名 dashboard 401、鉴权读取及五份静态资产字节一致、no-store 通过；订阅/设备身份指纹保持。部署前后 IPv4 全表路由与 ip rule 指纹、mihomo/wg-quick@sna-commercial/中继 timer InvocationID/MainPID/ActiveState 相同。公网 HTTPS 新仪表盘、认证 session-cookie/CSRF 代理和读取 12 客户通过；不可信 Origin 403，WG 管理入口响应正常。

## 风险与回滚

180 天服务期限与 30 天流量账期分别表示，不清零旧用量。授权可用不等于公网连通；计量按现有中继周期同步，页面有滞后状态。源机代理状态只覆盖已接入的本机源，其他源机不伪称就绪。

回滚只恢复该备份中的文件并重启商业控制 API，CLI 恢复两个模块；Caddy 恢复备份校验并 reload。不要把 SQLite 备份覆盖回正在运行的数据库，否则会丢失后续流量、客户和租约。新增表与索引可保留。操作前核对后续改动。
