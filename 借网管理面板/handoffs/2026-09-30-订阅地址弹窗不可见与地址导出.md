## 2. 缺陷与根因

三个缺陷，前两个共同造成"生成后完全看不到地址"。

### 2.1 弹窗不可见（主因）

`src/server_network_assist/subscription_admin_ui/subscriptions.html` 的两个 `<dialog>`（`#address-dialog`、`#reauth-dialog`）写的是 Tabler 的 `class="modal modal-blur"`。

Tabler 顶层作者样式 `.modal{display:none;...}` **优先于浏览器给 `dialog[open]` 的 UA 样式** —— 作者样式源整体高于 UA 样式源，与选择器特异性无关。结果：`showModal()` 成功设上 `open` 属性，`dialog.open === true`，元素在 DOM 中，但计算样式 `display:none`、`getBoundingClientRect()` 为 **0×0**，屏幕上什么都不显示。

本项目 `subscriptions.css` 中本就有 `.address-dialog{width:min(640px,calc(100% - 2rem));...}` 规则，却从未挂到这两个 dialog 上，属**死代码**；`dashboard.html` 的 dialog 一直是正确类名，故只有订阅控制台中招。

**实证方式**：用 Playwright 加载真实 `subscriptions.html` + 真实 `tabler.min.css`，`showModal()` 后读取计算样式与矩形，并对比"运行时把 class 换成 `address-dialog`"的结果：

| class | display | 矩形 | 可见 |
|---|---|---|---|
| `modal modal-blur`（修复前） | `none` | 0×0 | 否 |
| `address-dialog`（修复后） | `block` | 640×282 / 640×434 | 是 |

### 2.2 重认证后重放结果被丢弃（次因）

`fresh()` 门禁（管理员验证 5 分钟有效期）过期返回 **403**（非 401）。前端流程本身正确：弹重认证框 → 重新登录拿新 CSRF → **重放一次**原操作。但重放拿到的返回值被**直接丢弃**，只跑了 `refresh()`。

后果：客户与令牌在服务端**已创建成功**，用户却只看到"需要重新验证身份"，地址永远不出现。与缺陷 2.1 叠加，"生成后看不到"成为必然。

**修复**：把结果回调 `onResult` 沿 `run()` → `request()` → `pendingRetry` → `submitReauth()` 传递，重放成功后调用它显示地址；6 处 action 调用点全部接上具名完成处理器。

### 2.3 窄屏水平溢出（附带发现）

390px 宽度下「补发开户入口」输入框的内联 `style="width: 22rem"`（352px）在 flex 行内无法收缩，把整页 `scrollWidth` 顶到 **427px**。不属于原始投诉，但同属"补发/查看地址"工作流，且违反本项目"窄屏不得溢出"的 UI 规则，一并修复。
