## 触发条件和现象

用户要求新的接入保护 GUI，自行打开、读取订阅和确认借网；同时报告屏幕反复闪烁。更新流程未主动打开 GUI，旧 GUI 在工作期间已运行，不能结束它以覆盖制品。

## 真实证据

旧客户端物理接入监测调用 PowerShell 未隐藏控制台；存在潜在闪屏来源，未确认每次用户观察均同源。新 EXE 为 PE Subsystem 2、Windows GUI，后台 Windows 辅助工具调用设 CREATE_NO_WINDOW。

最终 EXE：`artifacts/client-exe-gui-protected/ServerNetworkAssistClient.exe`，SHA256 `d6c2d527a106a761dca874c5207bfb7b7e87997b7fa45465ab3c40ff9c703312`，29,367,124字节。独立 check_audit 解包比对56项 manifest、包入口和29项目模块及9项资源，全匹配当前源码，没有运行 EXE。

安装结果 `artifacts/gui-local-install-result-20260917.json`：installed=true、client_started=false、old_backend_stopped=false、network_fingerprint_unchanged=true。指纹包含IPv4/IPv6路由、DNS及HKCU系统代理字段，不等同于所有网络配置全量快照。

## 根因

确定事实是旧版外部 Windows 探测未设置隐藏标记；推断其可能造成用户看到的控制台闪烁。当前工作只进行后台读取、隔离测试和构建，不反复打开客户端窗口。

## 修复方案与实施记录

复用 Framework7 9.1.3 iOS List View / Dialog 组件，MIT许可证随客户端资源保留，未引入新的自行设计框架。接入保护显示物理网络、校园接入、订阅入口、个人校园账号四项，手动按钮只做检测。读取订阅后用现成 Dialog 列出授权节点、限额和限速，连接前再次确认。

未借网且无待恢复记录时跳过持续物理网络快照，借网期间仍监测接入变化和个人认证状态；后台PowerShell/wg/sc/icacls调用隐藏控制台。windowed EXE的退网失败（含SystemExit）与缺后台--show错误用可见消息框反馈，独立CLI继续保留原输出。

## 用户操作

1. 自己关闭已有旧窗口，再打开桌面“借网客户端”；如系统要求管理员授权，由用户确认。
2. 点击“检查接入 · 不更改网络”查看状态；热点保留原出口，不能启动借网。
3. 校园订阅地址为内网入口，需用户自己连接可直达4090的校园Wi-Fi或有线网络后读取。无需浏览器打开该地址。
4. 将私下提供的订阅地址粘贴，点击“读取订阅”；弹窗列出授权源网，读取不创建借网隧道。
5. 选择源网节点，点击“启动借网”并确认；客户端重新验证接入与个人账号状态，实际握手通过后才显示借网。
6. “退出组网 · 恢复原网络”保留窗口和订阅；正常关闭窗口也执行退出。最小化进入托盘。
