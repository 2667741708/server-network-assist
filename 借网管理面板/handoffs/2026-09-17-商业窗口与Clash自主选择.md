# OPS-NET-018 / ERR-NET-018：商业窗口与 Clash 自主选择

- 日期：2026-09-17；关联 REQ-NET-018、TEST-NET-026。
- 状态：源码修复、隔离回归、制品核验及本机只复制安装完成；新版真实 TUN/Verge 重启全流程尚未验收。
- 影响：Windows 客户端；本机和 d321 仅进行了节点只读测量。本机未启动新版、未修改网络配置。

## 触发条件和现象

用户看到 Python 图标及系统窗口边框，要求外观更商业；还报告启动 Clash Verge 后其他节点超时，要求入网后仍能自主启动 Clash 和选择代理。

## 根因与实现

确认的外观缺口：PyInstaller 未设置 EXE 图标；pywebview 使用系统标题栏。新增品牌 EXE 图标和 Windows 产品信息、进程 AppUserModelID、自定义无系统标题栏窗口，保留品牌标志、拖动、最小化、最大化/还原和关闭。关闭仍经过原生 closing 恢复逻辑，恢复失败允许阻止关闭。窗口桥接只暴露三个窗口动作，外部页面无法操作。

确认的共存缺口：已有配置文件但 Clash 关闭时，缺失的 Controller 会触发后台异常；Verge 重生成原始配置时，被当作代理字段冲突；配置文件未变但运行内核绑定丢失时，提前返回不重新配置。修复 expected-offline 为可选代理、允许从此前原始字段重生成、复核内核实际报告的绑定字段，恢复隧道作为代理底层出口。

用户 mode、TUN enable、系统代理和节点选择继续由用户控制。保留原订阅/proxies/rules；重载时只恢复仍存在的策略组选项。用户新增的不同接口/DNS字段不会强行覆盖，退出按字段所有权恢复。升级新增 DNS 字段先保存原值，避免退出时丢失用户配置。

节点专用 DNS 使用 IP 字面量 HTTPS DoH 并显式绑定入网隧道，避免依赖未认证物理网络或节点自身形成解析循环；不关闭 TLS 验证。使用已实测可达的 223.5.5.5 和 1.1.1.1；本次 1.12.12.12 探测失败，不作为主解析器。

实现：`client_native.py`、`client_ui/index.html`、`client_ui/client.css`、`client_ui/client.js`、`client_clash_coexist.py`、`build_client_exe.py`、`client_windows_version.txt`。构建快照同时保留另一任务已有的启动反馈代码，不回退其他编辑。

## 安装与回滚

本机快捷方式统一为“纯享入网”，复用既有 protected 数据目录；只清理指向本程序的旧“入网客户端”快捷方式，不删除订阅及旧程序版本。安装报告确认选定路由/DNS/WinINET 代理指纹不变；无后台停止和客户端启动。

并行任务使原构建输入发生变化后，使用 `scripts/stage_brand_build_snapshot.py` 固定构建输入并独立构建、核验，避免共享 PyInstaller 临时目录干扰。最终安装哈希和路径见制品 verification 与 local-install 报告。

需要回退时，只将拥有的桌面快捷方式指回先前版本；正在运行时先通过托盘恢复并退出。不要覆盖新订阅或清理管理隧道。未执行的跨平台、无线及系统重启测试仍保留为未验证。
