# OPS-NET-023：商业物理出口与客户自主代理

关联 REQ-NET-023 / TEST-NET-031。按用户要求先完成所有实现代码及测试脚本，再统一执行验收；不调整操作员本机网络。

## 已实现

- 源网登记、新订阅、已有授权迁移、租约 DTO 和中继策略接通 `source_proxy` / `physical`。
- SQLite 给既有 `line_grants` 增加默认空配置列，旧授权保持原出口。已有授权显式迁移撤销旧租约，重新入网更新 DNS。源网编辑只影响新签发的订阅。
- 管理网页新增出口配置，CLI 新增 `grant set-egress`；修复 Angular 源网编辑原有的自调用递归。
- Linux 物理客户使用来源 `/32` + 商业入接口的优先级 100 规则、独立路由表和终止性 unreachable 默认路由；检查物理接口、网关所在子网及外来路由/规则冲突。
- 单个中继允许不同客户使用不同出口，nftables按授权来源限制出口并 NAT，拒绝源机本机、管理网段、客户横向访问、IPv6和物理客户的 fake-IP 目的地址。
- 持久化所有权、文件锁、到期/额度撤销与独立路由清理；控制端或计量上报失败仍执行本地到期检查。正常恢复重建 WG、nftables及 TC，日志失败不阻塞主操作。
- 默认代理出口的中继 API 继续使用旧字段结构；物理客户才增加新路由字段，避免破坏旧版 Windows 严格校验器。

## 自动及隔离验收

出口/中继/数据库/API/CLI/订阅相关回归 61 项、客户连接/握手保护/恢复/Windows 中继相关 45 项，最新联合运行合计 106 项全部通过。新增回归覆盖失败重试时清理历史出口策略并保留累计计量。Angular 生产构建通过，初始 bundle 超过警告预算约 16.7 kB，未达到错误阈值。

浏览器 fixture 全部拦截网络请求，390px 小屏验证签发、完整长地址、重新读取、补发、源网出口保存及客户授权出口迁移。两类出口操作均重新认证、携带当前 CSRF、清除确认凭据、不保存到浏览器存储；长名称与 ID 不溢出。

4090 临时 Linux namespace 验收使用真实 WireGuard、nftables、NAT、HTB/ingress policer和策略路由，13 项通过：

1. 正在运行的模拟 TUN 不抢占物理客户流量。
2. 源端 TUN 删除后物理出口仍可用。
3. 真实 WG 字节计量。
4. 软件重建后规则、firewall及 peer 恢复且无重复规则。
5. 物理接口失效时禁止回落到其他出口。
6. 重新接入恢复。
7. 额度撤销真实 WG peer。
8. 额度撤销来源规则。
9. 撤销后客户不能转发。
10. 原主路由保留。
11. 原策略规则保留。
12. owned 独立表清空。
13. 临时 namespace 全部清理。

发现并修复：缺失 nftables 表时须先重建共享集合，再添加 peer 元素。测试网卡 DOWN 会由 Linux 删除 fixture 手工默认路由，重接入模拟 DHCP 重装该 fixture 路由；中继本身不恢复用户主默认路由。

## 4090 → D321 真实验证

独立 120 秒 systemd 恢复任务在切换前建立，D321 有独立关闭测试代理任务。仅临时改 D321 当前授权 peer 的出口，不改客户数据库/订阅或主路由。

- 源端停止商业轮询以免覆写临时策略，暂停 gateway-health 并停止 Mihomo；两次采样均证实 core inactive、Meta 不存在、guardian 未运行、D321 物理出口策略 active。
- 受控源端停止窗口记录为 `1789631162` 至恢复 `1789631205`，约 43 秒。所有客户验证在手动恢复前执行，未等到自动回退。源端与 D321 时钟有少量差异，以调用顺序及源端采样确认窗口。
- D321 本机代理开启后 ChatGPT / 百度返回 HTTP 200、TLS 校验 0；Codex 真实模型回复 `CLIENT_PROXY_OK`，退出码 0，没有超时。
- 第一次 Google（5 秒连接阈值）超时；独立重试 Google 204 / YouTube 200，TLS 校验 0。没有宣称所有首轮请求或长期机场稳定性通过。
- D321 → 4090 / 5080 / D408 校园 SSH 22 成功，并使用原物理校园网关。4090 → D321 / 5080 / D408 成功；恢复后 5080 / D408 → D321 成功。
- D437 校园 SSH 仍超时，与此前基础不可达一致，不能记为全组网通过。
- 源端恢复原 state/nftables，删除临时物理规则/表，恢复 Mihomo/Meta、两个 timer，配置哈希未变；D321 恢复 ProxyEnable=0、7897未监听，客户隧道仍 active。临时代理恢复任务已删除。
- 恢复并部署后无本机代理的 D321 Codex再次收到 `SOURCE_NETWORK_OK` 且 `turn.completed`；该旧测试工具首次返回时进程尚在运行，因此不把它的工具返回码当成 Codex最终退出码。
