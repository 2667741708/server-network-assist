## Windows 本机故障与边界

本次曾通过本机 PowerShell 启动客户安装程序，再通过客户后台安装 `snaa6e13eef32c2` WireGuard 隧道，并自动改写本机 Clash 的接口绑定、分流和 DNS。该动作确实调整了本机网络，不能声称“只有检查”。Windows 本机验收中在校园 SSH 检查时超时，用户随后报告完全断网并明确禁止继续本机网络变更。

本轮未执行 Windows 验收脚本的 `tun-on` 动作。禁止之后的只读检查显示客户借网隧道与活动记录已不在，只剩原有管理 WireGuard；当前 Clash TUN 为 `Meta` 且开启，公网路由进入 Meta；校园源机路径通过 WLAN 网关 `192.168.43.1`。不能据此确认当前断网仍由客户 WireGuard 引起，也不能认为手机/非校园网关能够访问校园源机。

客户软件此前把“服务安装成功”直接当作“已连接”，缺乏对应源机握手确认；修复加入近期握手检查和失败回退，仅在服务器部署验证。本机停止测试后台及禁用应用自动启动的管理员授权被取消，操作未执行。后续没有再次尝试本机网络变更。已在 4090 撤销本次专用 Windows 测试账号 `cus_160a2a9143494c7fa5ef57c01a8dabdc`；不影响其他客户。

Windows 共存代码的回归测试通过，实际网络验收失败/中止；软件重启、退网恢复和 Windows 原网络可用性不宣称通过。后续 Windows 只能在用户明确指定的其他服务器验收；本机恢复需另行明确授权。
