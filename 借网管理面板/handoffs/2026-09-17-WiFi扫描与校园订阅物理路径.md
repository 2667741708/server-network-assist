# OPS-NET-012：WiFi 扫描与校园订阅物理路径

- 日期：2026-09-17。
- 状态：源码、隔离回归、真实只读无线扫描及本机只复制安装已验证；真实校园无线入网未执行。
- 关联：REQ-NET-012、ERR-NET-010、ERR-NET-012、TEST-NET-020；继承 REQ-NET-002/003/007。

## 触发条件和现象

用户要求 Windows 入网客户端在仅有 WiFi 时可识别接入，提供 wifiscan，确认校园局域网后通过该物理路径解析订阅、定位源网并入网。现有订阅请求禁用系统 HTTP 代理，但仍使用系统 DNS 和路由，没有绑定已确认的物理校园网卡；现有接入报告未明确区分 WiFi/有线，也没有无线扫描按钮。历史校园无线失败不能据这些代码缺口直接确定根因。

## 实施

- `client_wifi.py` 使用 Windows 原生 WLAN API 扫描并读取无线列表，返回 SSID、网卡、信号、连接与加密状态；释放 API 缓冲及句柄，位置权限拒绝、服务未运行和没有网卡均提供建议。扫描异步，因此明示列表可能包含缓存；不连接、断开或修改无线配置。
- 客户端接入帮助提供“扫描 Wi-Fi”和“检查校园接入”。长 SSID 和网卡名称换行、可选中，列表竖向滚动；以 textContent 写入无线名称。接入报告显示 WiFi 或有线；地址政策检查与实际校园服务可达分别展示。
- `client_attachment_windows.ps1` 返回每个物理接口的 IPv4 DNS，合并重复的 IPv4/IPv6 系统查询。查询上限从 12 秒调整为 30 秒，超时明确为检测未知，不当作没有网络；后台保持隐藏控制台。
- `client_lan_transport.py` 在请求前调用现有校园地址/默认出口保护；TCP 和 DNS UDP socket 同时绑定物理接口及 IPv4 源地址。域名通过该接口的 DNS 解析，不回退系统解析器或代理。DNS 失败、截断、错误交易/问题和 Clash fake-IP 响应均拒绝。当前为 IPv4 A 查询，DNS 截断响应不实现 TCP 回退，而是清楚报错。
- `client_online.py` 将 Windows 默认的开户、订阅读取和租约请求接入物理传输；测试注入 opener 保持离线。HTTPS 保留证书链、主机名校验和原域名 SNI；跨域跳转在发送下一请求前拒绝。
- `ClientPanel.online_connect` 仍先检查个人账号未在线，再取得授权租约；重新检查物理网络未变，通过校园接口解析源网 Endpoint，然后安装客户专用隧道。失败走现有退网/租约释放；仍以对应公钥的近期握手作为连接门槛，不以订阅下载或 UDP 端口猜测替代。
- 可信范围沿用当前源码已有的 `10.20.0.0/16` 和 `10.126.0.0/17`；不根据 SSID 开放所有私网，非校园热点及未配置的 IPv6 默认出口保持拒绝。

## 使用与回滚

关闭旧客户端窗口后从桌面“入网客户端”重新打开。展开“接入保护与帮助”，扫描附近 WiFi；用户自行连接校园网络，读取管理员订阅。客户端先验证校园物理接入，再通过该接口获取授权源网列表；选择源网并确认开始入网。个人账号在线/未知仍保持个人网络，不自动退出账号。

本轮仅增加新哈希目录并更新桌面入口；沿用 `gui-protected-20260917` 配置，旧 EXE 保留。需回退时关闭窗口、确认客户自有状态恢复后，将快捷方式指回保留的旧制品，不停用管理 VPN。
