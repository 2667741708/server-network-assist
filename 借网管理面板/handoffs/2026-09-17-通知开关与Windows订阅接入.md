# OPS-NET-025：通知开关与 Windows 订阅接入

- 日期：2026-09-17。
- 状态：代码及隔离验证完成；D321 新 EXE 和快捷方式已安装，当前旧后台未重启，原生新版交互待下次打开验证。
- 关联：REQ-NET-025 / TEST-NET-033。
- 范围：Windows 纯享入网客户端。操作员电脑仅构建、隔离测试及文件复制，不修改真实网络。

## 触发条件和现象

用户希望关闭频繁通知，并核实 D321 是客户自己的代理还是源机代理、另一台 Windows 电脑如何订阅。

## 真实证据

只读检查 D321：系统代理开启，本地代理端口监听；生成的 Clash 配置 mode=rule、tun.enable=false。客户隧道 sna84f35f4bb267 仍运行，Endpoint 10.20.32.13:51910。

4090 真实状态：Mihomo 及 MetaTUN 就绪；中继 check 显示两个在线客户均 physical，主路由及已有策略规则与基线一致，校园 D321/5080/D408 TCP 可达。此轮未新做公网流量抓包，不把配置检查当作每个应用的请求归因。

## 根因

原托盘处理每个事件均发送 balloon，没有持久化通知偏好；网络切换前后同一事件会两次提示，周期错误可反复打开窗口。此轮没有编辑 D321 的机场订阅，也没有历史机场 URL 基线可用于证明此前从未改变；商业出口授权 physical 是独立配置。

## 修复方案与实施记录

新增 client_preferences.py 原子持久化设置；GUI 复用已有 Framework7 toggle，托盘提供勾选项；API 沿用本机令牌、Host 和 Origin 校验且不调用网络变更。关闭全部托盘 balloon，保留错误窗口和页面状态；同类错误 60 秒内合并，重新入网开启新的提醒周期。通知失败不影响退出恢复。

EXE revision 为 20260917-notification-settings，SHA256 为 6FBE2DB6A818CF32C8CF28A1683CA158AAD30BE584E22C3A4E6FE0E0F6F67DAB。D321 桌面“纯享入网”指向 gui-6FBE2DB6A818 新目录，保留原数据目录。安装报告 installed=true、client_started=false、old_backend_stopped=false、network_fingerprint_unchanged=true。

## 验证结果

53 项后端回归通过；Framework7 headless fixture 全部通过，包括点击真实 toggle、UI 重载保留设置、通知操作不入网/退网、长文本和原有操作。EXE 构建通过；安装前后路由/DNS/当前会话系统代理指纹相同。未运行新版原生 EXE、未新增客户实机连接，避免打断 D321 当前连接；没有宣称新电脑真实验收完成。

## 风险与回滚

已运行旧版仍使用旧逻辑。用户退出旧程序、确认原网络恢复后再双击新版，展开通知设置关闭弹窗。若回滚，恢复快捷方式原目标，保留订阅数据；无需更改服务器代理或客户网络配置。
