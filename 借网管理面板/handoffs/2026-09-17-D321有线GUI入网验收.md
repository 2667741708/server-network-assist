# OPS-NET-017 / ERR-NET-017：D321 有线 GUI 入网验收被控制运行时阻塞

- 日期：2026-09-17；关联 REQ-NET-017、TEST-NET-025。
- 状态：只读网络证据已验证；新的 GUI 入网未执行，整体验收未通过。
- 范围：DESKTOP-TD6B9GN / d321-titan，Windows 10 build 19045，源网 C201-4090。

## 触发条件和现象

用户要求驱动 d321 Codex CLI，通过 computer-use 操作现有入网客户端。CLI 已在登录用户的交互会话实际执行技能。唯一客户端窗口可列出、激活，但刷新选择、重试和重置后截图仍失败：`SetIsBorderRequired failed: 不支持此接口 (0x80004002)`。纯 accessibility 只有窗口及标题栏，没有入网按钮。未凭未观察的坐标点击。

官方 browser-client 备用入口按技能恢复规则尝试后返回 `No browser is available`，浏览器后端清单为空。未使用 API/CLI connect 代替 GUI 点击。

## 真实证据

- 有线 Intel I219-V、以太网 2、ifIndex 16、10.20.31.134；Wi-Fi Disconnected。
- 初始已经存在借网会话：Endpoint 10.20.32.13:51910、客户 10.213.40.7/32、WG 握手约 78 秒；服务端已有租约和实际字节计数。该会话在本次点击前就存在，不能算本次 GUI 点击成功。
- 约 12:29:34 原有会话出现 `left_network`、`lease_check_failed`，随后借网停止。native 日志只有 `native_window_shown`，无足够异常细节。
- 12:41:56 独立完整审计：configured=true、active=false、recovering=false，无有效租约；校园 TCP 9182 可达，公网路由为物理以太网，禁用 HTTP 代理、严格 TLS 的 api.github.com HTTPS 探测失败。fleet-titan 仍 Running。
- 退网后既有身份的签名订阅读取仍成功，授权源网 1 个。源机绑定校园 IP 对 d321 TCP 22 连接也成功。

## 根因

已确认：目标 Windows 环境不支持截图所需接口；官方浏览器运行时未发现后端，新 GUI 操作被控制运行时阻塞。未确认：原有借网自动退网具体发生于租约还是代理兼容检查，不能仅凭笼统事件文案认定 Clash 故障。

## 实施与验证

新增任务脚本：`scripts/titan_wired_gui_audit.py`、`titan_wired_codex_runner.py`、`titan_wired_codex_task.ps1`、`titan_wired_codex_status.py`、`titan_wired_codex_phase2.py`。修复审计的 PowerShell 中文输出编码；辅助日志不阻塞主操作。未修改产品代码、系统代理、Clash、校园账号、管理隧道或操作员本机网络。

既有借网停止导致 CLI 模型通道失败，使用仅该 CLI 进程的临时管理 CONNECT 通道恢复：源机 WG 10.203.49.1:19097，只允许 d321 的 10.203.49.3 且仅允许 chatgpt.com:443，转发源机现有 loopback 代理，15 分钟自动到期。实现 `scripts/d321_codex_control_proxy.py`。这条通道不计入借网公网验收。

源机默认 LAN SSH 超时后经身份探测改用已配置 zn 路径。该超时不是 d321 校园互访失败证据。
