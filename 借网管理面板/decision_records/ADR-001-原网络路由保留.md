# ADR-001：保留原网络，隔离借网出口

日期：2026-09-16。状态：方案已确定，待实施。关联：[ERR-NET-001](../error_traceability.md)、[REQ-NET-001](../requirements_traceability.md)。

## 决策

1. 原网络主路由表保留原网卡、默认网关和已有静态路由，Linux 借网接口不向主表添加全局 `/1` 路由。WireGuard AllowedIPs 与操作系统路由安装分别控制。
2. 借网默认出口进入独立表。策略规则先处理本地、端点、管理连接及内网例外，再处理借网公网流量；防止隧道端点递归进入隧道。
3. 原网络入站连接通过连接标记保护回程，必要时使用独立原网络表；该表保留原网关并随原网络变化更新，不能从已被 VPN 污染的状态建立基线。
4. 校园网范围不能仅从直连子网推断。保留已确认范围；10.0.0.0/8 可作为本部署候选，但需明确 VPN 和管理网段例外，不能对所有部署无条件硬编码。
5. Windows 采用平台对应路由机制，验证同等行为；Clash TUN、其他 VPN 与 DNS 也纳入冲突检测。
6. 单客户端只允许一个方案控制公网出口。管理专用隧道可保留。切换必须处理旧规则、服务和自动维护任务，不以关闭 GUI 开关替代清理。
7. 退网仅撤销自己拥有的路由、规则、DNS、代理和服务修改。保留操作后用户的新变更，冲突时报告而非盲目恢复。

## 为什么不能保证所有路由完全不变

借网改变公网出口；目标是完整保留原内网与入站回程逻辑，并在退网恢复原配置。校园网隔离或服务器自身防火墙禁止的访问，不能仅通过路由修复保证可用。

## 验收与恢复

验收见 [test_reference.md](../test_reference.md)。部署前保存可靠基线、配置所有权及管理连接；使用超时回滚和独立管理通道。每个平台必须实测后才能宣称支持。
