# 澜桥源网服务器与客户端借网架构教程

> 本文依据 2026-09-21 的代码、部署文档和只读现场核对编写。重点介绍当前“商业订阅客户端”链路；末尾另行说明管理台 SSH 编排的实验室借网，两者不要混用。

## 1. 一句话理解“借网”

借网不是把源网服务器的账号、SSH 权限或代理订阅交给客户端，而是：客户端先通过订阅服务获得一张短期、设备绑定的通行证，再建立 WireGuard 加密隧道；源网服务器只允许该设备的单一隧道地址经指定物理出口或源机代理访问公网。

```text
客户端应用
   │ 普通 IPv4 流量
   ▼
澜桥客户端（本机后台）
   │ 安装临时 WireGuard 路由
   │ 加密 UDP 隧道
   ▼
C201-4090 源网服务器
   ├─ WireGuard peer 鉴权与隔离
   ├─ nftables 防火墙与 NAT
   ├─ tc 上下行限速
   ├─ 真实转发字节计量
   └─ 物理出口 enp4s0，或显式选择的 Mihomo/TUN 出口
          │
          ▼
        公网
```

## 3. 五个核心组件

### 3.1 订阅与管理控制面

控制面负责保存客户、套餐、源网线路、设备、授权、租约和用量账本。核心数据位于 SQLite，管理员可通过订阅管理页或管理命令维护。

它只做策略决策：谁可以连接、可以选择哪些源网、租约多久、速度和流量额度是多少。它不会把 SSH 凭据交给客户，也不会让客户执行管理命令。

### 3.2 客户端本机后台

澜桥客户端由本地界面和高权限后台组成：

- 界面负责显示订阅、源网线路、到期时间、额度、状态和错误。
- 后台只监听回环地址，通过随机本机令牌保护。
- 后台生成 Ed25519 设备签名密钥和 WireGuard 密钥。
- 后台申请、续租、释放租约，并安装或停止自己拥有的 WireGuard 隧道。
- 客户端不具备管理端 `/api/fleet/*`、SSH 终端或凭据库能力。

### 3.3 在线设备认证与短租约

首次开户注册使用一次性 `#enroll=...` 令牌。注册后，客户端每次请求都携带设备 ID、时间戳、随机数和 Ed25519 签名。服务端拒绝过期时间戳、重复随机数、错误签名和被撤销设备。

客户端选择源网后申请短租约。租约把以下内容绑定在一起：

- 客户与设备；
- 被允许的源网线路；
- WireGuard 客户公钥和唯一 `/32` 地址；
- 中继 Endpoint、公钥和接口；
- 到期时间、DNS、允许路由；
- 上下行限速和总流量额度；
- 物理出口或源机代理出口模式。

短租约的意义是：暂停客户、撤销授权、超额或到期后，无需等待长期配置失效，客户端续租会被拒绝，中继也会在下一次协调中移除 peer。

### 3.4 WireGuard 数据面

客户端拿到租约后生成 WireGuard 配置，但不会接受服务器下发任意脚本。配置包含客户端私钥、隧道地址、中继公钥、Endpoint、DNS 和允许路由。

当前实现常用两个 `/1` 路由代替直接覆盖 `0.0.0.0/0`：

```text
0.0.0.0/1
128.0.0.0/1
```

两条路由合起来覆盖全部 IPv4 公网，同时可为订阅 API、源网 Endpoint、校园认证地址和管理通道保留更精确的直连路由，避免“隧道刚启用就把自己的控制连接切断”。

WireGuard 握手成功后客户端才报告连接成功。握手失败时，客户端停止新隧道并恢复原网络，而不是保留半生效状态。

### 3.5 中继执行层

源网 Linux 中继以“一个租约对应一个 WireGuard peer”为最小单元：

- `allowed-ips` 固定为客户唯一 `/32`，防止冒用其他客户地址；
- nftables 只允许客户流量走指定公网出口并执行 NAT；
- 阻断客户访问管理网段，也阻断同一客户接口上的客户互访；
- `tc` 按客户地址实施上传、下载限速；
- `wg show ... transfer` 的单 peer 收发增量作为真实用量；
- 租约过期、超额、暂停或撤销时删除 peer、限速和授权地址。

`server-network-assist-relay.timer` 周期执行以下闭环：

```text
读取 WireGuard 计数器
        ↓
向控制面上报增量用量
        ↓
拉取当前期望租约集合
        ↓
对比本机实际 peer
        ↓
新增 / 更新 / 撤销 peer、nftables 与 tc 规则
```

因此服务端数据库是授权事实来源，中继本机状态是执行状态，两者通过周期性 reconcile 保持一致。

## 4. 完整借网时序

### 阶段 A：管理员签发服务

1. 管理员登记源网：Endpoint、公钥、客户地址池、中继接口、物理出口接口、物理网关和 DNS。
2. 管理员创建客户及套餐，设置有效期、设备数、额度、上传和下载速率。
3. 管理员把一条或多条源网授权给客户。
4. 系统生成一次性开户注册地址，例如：

```text
http://10.20.32.13:9182/#enroll=一次性令牌
```

`#` 后的片段不会随普通 HTTP 请求发送给服务器；澜桥界面读取后再通过受控 API 完成注册。

### 阶段 B：客户端首次注册

1. 客户端先确保所在 Wi-Fi 已完成校园认证，能够访问 `10.20.32.13:9182`。
2. 用户粘贴完整订阅地址或订阅码。
3. 客户端本地生成设备签名密钥和 WireGuard 密钥。
4. 客户端用一次性令牌提交设备公钥、WireGuard 公钥和设备标签。
5. 服务端验证令牌未使用、未过期且客户仍有效，然后创建设备记录。
6. 客户端保存设备身份；一次性令牌不能重复用于另一设备。

### 阶段 C：查看和选择源网

客户端签名请求 `/client/v1/` 接口，取得经过脱敏的可用线路。界面只显示线路名称、可用性、出口类型、速率、额度和到期时间，不显示服务器 SSH 地址、私钥、管理网关或租约内部 ID。

### 阶段 D：开始借网

1. 客户端向控制面申请所选线路的租约。
2. 服务端检查客户、设备、授权、设备数量、有效期和流量额度。
3. 服务端生成短期租约及中继策略。
4. 中继定时任务取得期望策略，将该设备作为新 WireGuard peer 加入 `sna-commercial`。
5. 中继写入客户隔离、NAT 和限速规则。
6. 客户端安装本机 WireGuard 隧道和保留路由。
7. 客户端等待真实 WireGuard 握手，并执行联网探测。
8. 全部成功后，界面显示“正在借用源网”。

### 阶段 E：数据传输

以物理出口为例：

```text
d321 应用发包
  → Windows 路由选择商业 WireGuard 隧道
  → UDP 加密发往 10.20.32.13:51910
  → sna-commercial 解密
  → nftables 验证来源 /32 和目标范围
  → tc 执行速率策略
  → 经 enp4s0 做 NAT
  → 10.20.32.1 校园物理网关
  → 公网
```

返回流量按相反路径回到客户端。源网看到的是每个 peer 的隧道字节；公网看到的出口地址是源网物理出口或所选代理/TUN 出口的地址。

### 阶段 F：续租、计量和撤销

- 客户端在租约到期前申请续租。
- 中继按周期上报 peer 收发增量；控制面做幂等聚合。
- 超额、客户暂停、授权撤销或服务到期后，续租被拒绝。
- 中继下一轮协调删除 peer 和策略，默认延迟约为一个 10 秒周期加请求耗时。
- 客户端发现租约失效后停止商业隧道并恢复原网络。

### 阶段 G：主动退网

1. 客户端先停止自己拥有的 WireGuard 隧道。
2. 删除客户端创建的公共路由、DNS 和临时共存设置。
3. 恢复连接前保存的原系统代理和原路由状态。
4. 向服务端释放租约；即使释放请求暂时失败，本机退网也不应被阻塞。
5. 通过不走代理的 HTTPS 请求验证原网络是否恢复。

## 5. 两种出口模式

### 5.1 物理出口 `physical`

这是当前新订阅的默认方式。中继显式把客户流量导向 `enp4s0`、物理网关 `10.20.32.1` 和指定公共 DNS。即便 4090 本机正在运行 Mihomo/TUN，客户流量也不会因为默认路由变化而静默转入代理。

适合：希望借用源机真实校园/宽带公网、行为最容易解释和审计的场景。

### 5.2 源机代理出口 `source_proxy`

只有管理员为该线路显式启用，并且源机 Mihomo/TUN 被检测为就绪时才能签发。中继策略会把该客户流量送入受控代理出口。

适合：客户明确需要使用源机代理能力的场景。它不是客户端自行选择代理订阅，也不是把 `127.0.0.1:7897` 暴露给客户。

修改现有客户线路的出口模式会撤销旧租约；客户必须退网后重新入网，不能让一个活动租约中途静默换出口。

## 6. 校园接入为何是前置条件

澜桥可以借用源网的公网出口，但它不能替代客户端本机连接校园 Wi-Fi、获取局域网地址及完成校园认证。客户端至少要先能到达：

- 校园订阅 API `10.20.32.13:9182/TCP`；
- WireGuard Endpoint `10.20.32.13:51910/UDP`。

因此正确顺序是：

```text
连接校园 Wi-Fi
 → 完成校园认证
 → 能访问源网 API
 → 读取订阅
 → 申请租约
 → 建立 WireGuard
 → 借用源网访问公网
```

SSID 只用于提示，不能单独证明网络可用。真正的判断依据是接口绑定后的 API 可达性、Endpoint 可达性、WireGuard 握手和最终联网探测。

## 7. 管理员操作教程

### 7.1 登记源网

源网配置至少需要：

```json
{
  "id": "c201-4090-commercial",
  "name": "C201-4090 商业源网",
  "endpoint": "10.20.32.13:51910",
  "relay_public_key": "<源网 WireGuard 公钥>",
  "address_pool": "10.213.40.0/24",
  "relay_interface": "sna-commercial",
  "egress_interface": "enp4s0",
  "egress_gateway": "10.20.32.1",
  "egress_mode": "physical",
  "dns": "<已验证的公共 IPv4 DNS>"
}
```

不要在源网 JSON 中保存 SSH 密码、WireGuard 私钥或客户订阅令牌。

### 7.2 创建客户服务

日常推荐使用订阅管理页面，依次完成：

1. 选择“生成订阅”；
2. 输入客户显示名称；
3. 选择一个或多个源网；
4. 设置有效期、流量额度、上下行速率和最大设备数；
5. 需要代理出口时，仅对已经就绪的源网勾选源机代理；
6. 管理员重新认证后签发；
7. 通过安全渠道把完整开户注册地址交给客户。

当前入口包括：

- 校园管理入口：`http://10.20.32.13:9182/subscriptions.html`
- 管理 WireGuard 入口：`http://10.201.250.1:9180/subscription-admin/subscriptions.html`
- 公网 HTTPS 管理入口：`https://whm12.art/subscription-admin/subscriptions.html`

管理页面地址和客户订阅 API 地址是两个概念。校园客户的订阅地址应以 `http://10.20.32.13:9182/#enroll=...` 开头，不能把 `/subscriptions.html` 管理页面地址发给客户端。

### 7.3 日常检查

管理员应至少核对：

1. 活动租约数是否与中继活动 peer 数一致；
2. 最后计量时间是否持续更新；
3. 超额、过期、暂停或撤销客户是否仍存在 peer；
4. 实测速率是否接近套餐限速，允许隧道协议开销；
5. 商业接口、API 和物理默认路由是否正常；
6. 数据库及审计记录是否按策略备份。

## 8. 客户端操作教程

### 8.1 首次使用

1. 连接指定校园 Wi-Fi，并先完成校园网认证。
2. 打开“澜桥”客户端。
3. 粘贴管理员提供的完整订阅地址或订阅码。
4. 等待客户端完成一次性注册。
5. 检查客户名称、服务有效期、流量额度和可用源网。
6. 选择一条可用源网，点击“开始借网”。
7. 等待界面依次完成申请租约、建立隧道、握手和联网验证。

不要在“正在连接”阶段重复点击，也不要手工启动客户端生成的 WireGuard 服务；客户端需要维护隧道所有权和恢复记录。

### 8.2 如何确认真的在借网

必须同时满足：

- 客户端状态明确显示“正在借用源网”；
- 存在活动短租约且未过期；
- 商业 WireGuard 隧道处于运行状态；
- 最近握手时间持续更新；
- 收发字节随实际访问增长；
- 客户端联网探测成功。

只看到澜桥程序、桌面快捷方式或某个管理 WireGuard 隧道运行，都不能证明正在商业借网。

### 8.3 正确退网

1. 在澜桥中点击“退出借网”。
2. 等待客户端停止商业隧道并恢复原网络。
3. 确认界面显示原网络探测成功。
4. 如原网络仍不可用，先检查校园认证和 Windows 系统代理，不要立即删除所有 WireGuard 服务。

## 9. 常见故障与定位顺序

### 9.1 订阅地址打不开

按顺序检查：

1. 是否已连接正确的校园 Wi-Fi；
2. 是否已完成校园认证；
3. 客户端是否能直达 `10.20.32.13:9182`；
4. 是否把管理页面地址误当成客户订阅地址；
5. 一次性令牌是否已使用或过期；
6. 系统代理是否错误地接管了校园私网请求。

### 9.2 能读取订阅，但 WireGuard 不握手

重点检查：

- `10.20.32.13:51910/UDP` 是否可达；
- 源端 `sna-commercial` 是否启用；
- 中继是否已经取得该租约并添加 peer；
- 客户端和服务端 WireGuard 公钥是否对应；
- 客户地址是否唯一且属于 `10.213.40.0/24`；
- Windows 防火墙、校园网 UDP 策略或 MTU 是否阻断。

### 9.3 已握手但不能上网

重点检查：

- 客户端公共 `/1` 路由是否安装；
- DNS 是否来自租约且可达；
- nftables 是否允许该客户 `/32`；
- 是否存在正确的 NAT；
- `egress_mode`、`egress_interface` 和物理网关是否一致；
- 源机代理模式下 Mihomo/TUN 是否仍处于就绪状态；
- 客户是否已超额或租约即将被撤销。

### 9.4 退出后原网络未恢复

先使用澜桥的退网/恢复功能，不要全局清空路由或删除未知服务。检查：

- 商业隧道是否已停止；
- 两条公共 `/1` 路由是否已删除；
- 原 DNS、WinINET 代理和 PAC 是否恢复；
- 校园物理默认路由是否存在；
- 校园认证是否仍在线。

客户端只应清理自己记录为 owned 的资源。`fleet-titan`、管理 Hub、WSL、Docker、Hyper-V 或其他 VPN 的路由和服务不属于商业客户端，不能因排障而一并删除。

### 9.5 客户显示到期或超额但仍短暂可用

控制面拒绝续租后，中继需要等待下一轮约 10 秒的协调任务移除 peer。这个短窗口是周期执行模型的正常上界，不代表额度判断完全依赖客户端。

## 10. 安全设计与当前必须关注的问题

### 已实现的边界

- 客户端不知道源机 SSH 凭据；
- 设备请求使用 Ed25519 签名、时间戳和防重放随机数；
- 每台设备使用独立 WireGuard 公钥和 `/32`；
- 中继阻断管理网段和客户互访；
- 限速、计量和撤销由服务端数据面执行；
- 客户端仅能安装固定结构的 WireGuard 配置，不能执行服务端脚本；
- 退网具有原网络快照和 owned-resource 清理边界。

### 当前现场告警

`wg-quick@sna-commercial.service` 的启动记录提示：

```text
Warning: /etc/wireguard/sna-commercial.conf is world accessible
```

该文件可能包含源网 WireGuard 私钥，权限过宽是高风险项。应由管理员在维护窗口核对文件属主和权限，通常应限制为 root 可读写，并在修复后重新验证服务启动、客户端握手和回退；不要在未核对属主、备份与当前连接影响的情况下直接修改。

## 11. 与“管理台 SSH 编排借网”的区别

仓库还包含另一套面向实验室管理员的方案：管理台保存加密 SSH 凭据，通过 AsyncSSH 登录出口机和客户端，远程调用 root helper 配置 WireGuard、Linux iptables 或 Windows WinNAT，并在断开时恢复路由和代理。

| 对比项 | 澜桥商业客户端 | 管理台 SSH 编排 |
| --- | --- | --- |
| 使用者 | 普通授权客户 | 实验室管理员 |
| 客户端是否获得 SSH | 否 | 管理台持有受控 SSH 凭据 |
| 授权模型 | 设备注册、套餐、短租约 | 管理员创建网络方案 |
| 数据面 | 每设备 peer、服务端限速计量 | 方案级 WireGuard 与 NAT |
| 撤销 | 控制面＋周期 reconcile | 管理台 disable 与远端 helper 回退 |
| 适用范围 | 可运营、可计量的客户借网 | 自有服务器间临时共享网络 |

两套体系都使用 WireGuard，但控制平面、身份模型、计量边界和恢复机制不同。不能用管理 WireGuard 服务是否运行来判断澜桥商业借网，也不能把商业订阅接口当作 SSH 编排入口。

## 12. 最终理解模型

可以把整个系统理解为四层：

```text
业务层：客户、套餐、额度、有效期、源网授权
认证层：一次性开户注册、设备签名、短租约、即时撤销
隧道层：WireGuard 设备公钥、/32 地址、Endpoint、路由与 DNS
执行层：peer、nftables、NAT、tc、真实字节计量与恢复
```

“借网成功”必须贯穿四层：业务授权有效、设备认证通过、WireGuard 真正握手、源端转发策略真正生效。任何一层只显示“已配置”都不能单独证明客户已经通过源网访问公网。
