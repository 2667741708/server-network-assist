# Windows / Ubuntu 双向共享与代理选择

当前源码支持四种方向。Windows 出口与代理共享属于新增 Alpha 功能，请按下方验收流程验证自己的系统；自动化测试不等于四种组合均已完成实机验收。

| 出口 → 客户端 | 网络共享实现 | 可选择共享 HTTP/HTTPS 代理 |
| --- | --- | --- |
| Ubuntu → Ubuntu | WireGuard + Linux 转发 / iptables NAT | 支持 |
| Ubuntu → Windows | Linux 出口 + Windows 原生 WireGuard | 支持 |
| Windows → Ubuntu | Windows 原生 WireGuard + WinNAT | 支持 |
| Windows → Windows | Windows 原生 WireGuard + WinNAT | 支持 |

## 前提和升级

- 更新管理台源码并重新安装所有参与节点的辅助程序。旧版 Windows 辅助程序仅接受客户端配置，不能用于新出口功能。
- Linux 节点需要 `wg`、`wg-quick`、`ip`、`iptables`、`systemctl`、Python 3；使用 root 或明确授权的 sudo 账号。
- Windows 节点需要 WireGuard for Windows、PowerShell 5.1+、管理员 SSH 账号。作为出口还需要可用的 `Get-NetNat` / `New-NetNat` 和 Windows 防火墙命令；缺少组件的系统版本不能作为出口。
- 出口 UDP 端口必须对客户端可达。程序配置主机防火墙，不替你修改路由器端口转发或云防火墙。
- IPv4 共享，不接管 IPv6。隧道网段不能与现有网络重叠。一个客户端同一时间只能加入一个活动借网方案。

WinNAT 只支持一个内部 NAT 前缀。本程序检测到已有 WinNAT 时会拒绝创建新出口，不删除或复用 WSL、Docker、Hyper-V 等组件的 NAT。不要照搬清空 NAT 的命令来绕过检查；可选择另一台出口机。来源：[微软 NAT 配置文档](https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/setup-nat-network)。

## 两种模式

在“网络借助 → 方案设置 → 是否共享源机器的代理”中选择。

### 仅共享网络，不共享源代理（默认）

客户端的公网 IPv4 路由通过出口转发。源机器的手动应用代理不传递，客户端原有代理设置保持原样。若客户端原来就有失效代理，需通过桌面面板或系统设置单独排查。

**这不是绕过源机器 VPN/TUN 的开关。** VPN/TUN、透明代理及其他路由策略属于源机器的系统网络，转发流量仍可能受其影响。程序不会擅自关闭源代理软件、TUN 或改变其规则。

### 共享网络，同时共享 HTTP/HTTPS 代理

填写**源机器上的**代理 IPv4 和端口，默认示例为 `127.0.0.1:7897`。支持 HTTP 代理及兼容 HTTP 的 mixed 端口，HTTPS 通过 CONNECT。要求源代理当前在运行且该端口无需账号密码；不导入订阅、规则、PAC、认证信息或仅 SOCKS 的端口。

这是显式共享指定代理服务，不会实时同步源机器的代理开关。源服务停用或代理路径失效时验证失败；维护检查连续失败会回退，不自动改用直连。修改模式或源端口前必须先断开方案。

流量路径：

```text
客户端应用 → 出口隧道 IP:17897 → 源机器上的 HTTP 代理 → 目标网站
            └── WireGuard 加密 ──┘
```

出口中继只监听隧道地址；Linux 同时按已配置的 WireGuard peer IP 限制连接，Windows 防火墙限定隧道接口/子网。不会把 `127.0.0.1` 原样复制到客户端，也不会在 `0.0.0.0` 开放公共代理。Windows 使用原生 `netsh interface portproxy`，Linux 使用随辅助程序提供的标准库 TCP 中继。共享对象是本方案中的可信客户端。

| 客户端 | 自动设置的范围 | 不自动覆盖的范围 |
| --- | --- | --- |
| Windows | 安装/启用时 SSH 账号的用户系统代理（WinINET），备份原值 | 其他登录用户、WinHTTP 服务、独立代理配置的程序 |
| Ubuntu | `/etc/profile.d/server-network-assist-proxy.sh`（新登录 shell）、APT 专用配置；若存在 SSH 用户已登录的 GNOME 会话，备份并修改其代理 | 已启动 shell/进程的环境、非 GNOME 桌面、独立服务配置 |

Windows 桌面用户应与管理该主机的 SSH 用户一致。Ubuntu 已有 shell 请重新登录；已经启动的进程不会因为修改文件而自动更新环境变量。程序不会覆盖已有的同名代理文件；发生冲突时先完成之前的清理。

## 使用步骤

1. 添加并核对 SSH 主机指纹，探测各节点；安装当前辅助程序。
2. 选择 Windows 或 Ubuntu 出口、客户端列表、UDP 端口、隧道网段、出口地址和保留路由。
3. 选择是否共享代理；共享时填写源代理地址/端口。保存后启用。
4. 程序先验证出口，再建立客户端隧道，复检 SSH 和所选网络路径；共享模式使用明确的代理入口验证，避免只看直连而误判。
5. 逐个检查浏览器和实际使用的命令/应用。Windows 桌面面板同时显示直连与系统应用探测。
6. 管理台点击“断开并恢复原网络”，清理该方案资源并恢复代理。桌面面板的普通隧道开关仅停止服务，不负责完整清理方案。

## 回退与故障恢复

修改前写入恢复记录。Windows 记录本方案 NAT、转发开关、规则、端口中继、用户代理与临时路由；Linux 记录转发状态、临时路由、代理文件和 GNOME 原值。只清理本方案创建的资源。

外部修改过的 NAT 或 Linux 代理文件不会被直接删除。原 Windows 用户注册表未加载、原 GNOME 会话不可用、远端 SSH 失联等情况可能让代理恢复暂时失败；恢复记录不会丢弃。重新登录原用户、恢复连接后，在错误方案中再次点击“断开并恢复原网络”。

关闭浏览器或管理台不是断开共享。跨机器网络操作不能做到数据库式原子提交；本机确认定时器、维护检查与回退记录用于处理部分失败，不能保证掉电、内核故障或离线主机立即恢复。

## 验收记录与建议

新增自动化覆盖：模式校验与运行期不可改、共享配置传递、真实本地 TCP 双向中继与 peer 拒绝、源直连失败时的共享路径调度、丢失启用回复后的回退、部分 NAT/路由创建失败的恢复、外部改动保护。PowerShell 测试使用模拟系统命令，不会建立真实 NAT。

四种组合的现场验收应分别记录：系统版本、节点角色、源代理模式、SSH 可达性、客户端实际应用访问、断开后的路由/代理恢复、重启后的维护行为。本次开发未为这些组合主动切换生产服务器网络；不要把文档演示截图当作实机互通证据。
