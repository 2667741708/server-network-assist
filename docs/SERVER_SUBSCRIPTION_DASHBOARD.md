## 查看用户、权限和消耗

顶部汇总客户数量、当前可入网客户、有效租约、今日流量与累计流量。客户列表可按名称/编号/源网搜索，按状态和源网筛选；宽表支持横向滚动，长名称和地址完整换行。

每个客户显示：开户地址状态、服务可用性与原因、逐条源网授权及物理/源机代理出口、各线路到期时间、本账期已用/额度/剩余额度、今日与累计用量、套餐上下行限速、当前上下行速率、最后计量时间、设备上限与有效租约。可导出筛选后的 CSV，不包含订阅令牌、网址、私钥或设备公钥。

“详情 / 设备 / 变更记录”可查看设备、有效租约、最近 12 个账期和最近 10 次服务变更。可单独停用/恢复设备，需再次输入管理员凭据；不会删除其身份。行内“查看订阅地址”复用原受保护查看流程，需再次输入管理员凭据；未留存地址时禁用。横向滚动时客户首列固定可见。

## 客户归档、回收站、标签与备注

1. 点击客户行 **标签 / 备注 / 归档**，在当前窗口编辑。标签用中文或英文逗号分隔，最多20个，每个最多30字；备注最多4000字，仅管理员可见。
2. **只修改标签或备注**：保留“日常客户”状态，输入管理员凭据保存；不改变套餐、权限或现有租约。客户行“查看备注”可展开完整内容，搜索也支持标签和备注。
3. **归档不用的客户**：归档状态选择“归档”，保存后停用此客户并撤销其租约，保留原地址、设备、历史用量。它从默认日常列表隐藏。
4. **清理丢弃客户**：选择“删除至回收站”，效果是可恢复清理，账务和身份不永久删除。
5. **查看与恢复**：列表上方“客户分类”选择“已归档”或“回收站”，可叠加标签/服务/源网筛选。再次打开管理窗口，改回“日常客户”。恢复后服务仍停用，需在“修改服务”中明确启用；不续期、不清零流量，原撤销租约不会恢复。

顶部历史消费汇总包括归档与回收站客户。归档/回收站不能绕过分类直接开启服务；中继在正常同步周期移除撤销授权。

管理员 CLI 的原 `subscription show` 输出新增 `lifecycle`、`tags`、`notes`；原 `subscription update --customer CUSTOMER_ID --file change.json` 可更新这些字段。JSON 仍必须包含刚查询到的 `expected_version` 与 `expected_revision`。分类值为 `active`、`archived`、`deleted`；标签是字符串数组，备注是字符串。先查询并生成文件，不能复用旧版本号。

## 原地址不变的服务调整

2026-09-18升级：新建和修改均支持以下速度与期限设置。

- **解除上传 / 下载限速**：一键勾选两个方向的不限速；也可只解除某个方向。
- **自定义速度**：分别输入上传和下载Mbps，支持0.001Mbps精度，例如下载123.456、上传12.345。不限流量与不限速独立设置。
- **服务期限**：一个月30天、半年180天、一年365天、永久，或未来十年内任意日期。预设从当前时间起算；永久仍可随时停用或撤销。
- **生成订阅**：导航点击“生成订阅”，选择源网、流量额度、带宽与“有效期”，输入管理凭据签发。
- **现有客户**：客户行点击“修改服务”，选择带宽或期限；如需自定义日期，勾选统一更改期限并填入时间，保存后原订阅地址继续使用。

流量额度仍以30天为一个账期，延期不清零消费。服务期限可以永久，但交付给客户的一次性开户地址仍只可在24小时内兑换；已经绑定的客户端不受该开户有效期影响。不限速表示本服务端不设客户带宽上限，不保证出口固定速度。

1. 搜索客户，点击其行内的 **修改服务**。
2. 修改名称、服务启停、每账期额度、上传/下载限速、绑定设备上限；无限额度或不限速使用对应勾选框。
3. 如需续期，勾选“统一更改此客户所有线路到期时间”，选择30天、半年180天、一年365天、任意日期或永久。默认不勾选，以保留各线路原期限；点击“永久”会自动勾选更改期限。
4. 逐条线路选择启用/停用及 **物理宽带** / **源机代理**。选择源机代理要求其已运行并通过代理就绪检查；未就绪不能新增该权限。可在已有“源机代理控制”中显式启动 4090 Mihomo/TUN，再刷新数据。
5. 输入管理员密码或登录密钥，点击 **保存服务 · 保留订阅地址**。

后台在同一事务中保存，其他管理员或旧管理按钮在编辑期间改变客户/线路时拒绝过期提交，要求刷新。修改套餐会为此客户创建独立套餐，不改变共享原套餐的其他客户。保存后页面会提示是否需要重新入网。

- 提高额度、延长期限、改为不限速：保留原订阅地址、设备身份、已消费流量和账期起点。源端中继下一轮同步读取新限速，通常约 10 秒；客户端刷新订阅读取权限，无需重新开户。
- 物理/源机代理出口切换、停用客户或线路、额度降低到已用以下：撤销对应旧租约，源端中继下轮移除/更新授权。出口切换后客户必须重新入网。
- 降低设备上限前必须先停用多余设备；不会自动删除客户身份。
- **服务期限与流量账期不同**：180 天是线路可使用期限；额度仍按原套餐账期（当前月度套餐为 30 天）刷新。续期不清零本账期已用量，不把月度额度变成整个 180 天的一次性总额度。
- 地址是一次性开户注册地址。已兑换的地址可查看，但不能再次开户；已绑定客户端用原设备身份继续使用。尚未兑换且已留存的旧地址可显式恢复有效 24 小时，地址不变，也不取消一次性限制。

## 数据的含义与限制

今日按服务端本地日期分日；累计为此客户服务端已留存的各账期上行/下行之和，并非仅此电脑统计。上下行从客户视角显示。历史数据未记录时不会补造。页面约 15 秒自动刷新，编辑时暂停；计量约 10 秒同步，最后上报超过 30 秒显示滞后。有效租约与“授权可入网”都不代表实时公网连通测试成功。

读取失败时保留旧列表、明确标记刷新失败并禁用编辑/导出，重新刷新成功后再操作。登录退出会清空仪表盘；凭据不保存到浏览器 localStorage/sessionStorage。

## CLI

以下命令在 **4090 Ubuntu 源网服务器**执行，不在操作员 Windows 电脑执行。

查看全部客户：

```bash
sudo /opt/server-network-assist-relay/venv/bin/server-network-assist-service-admin --database /home/a/.local/share/server-network-assist-commercial/data/commercial-service.sqlite3 subscription show
```

查看指定客户（把 `customer_xxx` 换成真实编号）：

```bash
sudo /opt/server-network-assist-relay/venv/bin/server-network-assist-service-admin --database /home/a/.local/share/server-network-assist-commercial/data/commercial-service.sqlite3 subscription show --customer customer_xxx
```

将输出中的版本和 `revision` 复制到一个 `service-change.json` 文件。例如只升级无限流量/不限速，其余字段不修改：

```json
{
  "expected_version": 0,
  "expected_revision": "复制最新查询结果中的revision",
  "quota_bytes": null,
  "download_bps": null,
  "upload_bps": null
}
```

修改指定客户：

```bash
sudo /opt/server-network-assist-relay/venv/bin/server-network-assist-service-admin --database /home/a/.local/share/server-network-assist-commercial/data/commercial-service.sqlite3 subscription update --customer customer_xxx --file /home/a/service-change.json
```

如需续期，加 `expires_at` 字段（Unix 秒；`null` 为永不过期）。在服务器执行以下命令取得从现在起 180 天的值，再填入文件：

```bash
date -d '+180 days' +%s
```

逐线路变更使用 `grants` 数组，每项包含从查询取得的 `id`、布尔 `enabled` 和 `egress_mode`（`physical` 或 `source_proxy`）。不要提交其他客户的线路编号。

## 接口与实现

`GET /api/client-service/dashboard` 仅管理员会话可访问。`POST /api/client-service/action` 的 `subscription-update` 动作接受 `id` 和 `service`，要求 CSRF、近期管理员验证、`expected_version` 与 `expected_revision`，返回是否撤销租约/需要重连。数据响应禁止缓存。核心实现为 `subscription_dashboard.py`，审计表为 additive `commercial_service_changes`，不保存开户地址或私钥。
