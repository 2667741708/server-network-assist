# 停止借网，恢复客户端独立账号上网

“共享网络”页的“断开并恢复原网络”以共享方案为单位。一个方案内有多台客户端时，会恢复全部客户端并关闭该方案的出口资源；它不是单客户端退出按钮。

## 面板创建的方案

1. 在“共享网络”选择原方案，核对出口机和全部客户端。
2. 如果该方案只有要退出的一台客户端，点击“断开并恢复原网络”并确认。多客户端方案不能用此按钮只退出其中一台。
3. 等待状态显示“已停用”。如出现“恢复未完成”或 `cleanup_pending`，保留方案和主机凭据，修复 SSH 可达性后重试恢复，不要删除记录。
4. 在“诊断与恢复”复核默认路由、代理状态和公网探测。恢复范围是本方案记录并修改的路由、隧道、代理及出口辅助资源；不是整机任意历史配置的快照还原。

其他管理台创建的方案应回到原管理库恢复。新桌面库不会自动导入原管理台的凭据或操作记录。

## 已有脚本安装的隧道

v0.3.1 在“本机隧道”提供三种明确操作：

1. **临时断开**：停止所选服务，保留启动方式，下次开机仍可能自动连接。
2. **停止借网并禁用自动启动**：先保存服务原启动方式和运行状态，再停止并禁用服务（Windows Disabled；Ubuntu systemd mask）。完成后复查服务状态。仅作用于面板所在机器及所选隧道；不会关闭其他客户端或出口机。
3. **恢复原借网服务配置**：依据上述备份恢复启动方式和原运行状态。如果原来正在运行，会重新开始借网。没有备份时不猜测恢复。

这些操作随服务停止移除隧道拥有的路由，但不撤销旧脚本单独配置的持久路由、代理、计划任务或登录守护程序。应依据原部署脚本与备份逐项恢复。启动配置位于面板数据目录 `tunnel-recovery/`；失败保留记录，可修复原因后重试。安装面板不等于接管旧方案的所有恢复状态。

## 恢复原校园网脚本

先退出借网并确认校园网认证请求走客户端自己的物理网络，再在客户端原生系统运行原登录程序。否则当前认证查询或注销操作可能针对共享出口的会话。

本工作区另一个项目 `ysunetlogin_openwrt/netlogin.py` 支持：

```text
python netlogin.py current-status --json
python netlogin.py login-stdin
```

Ubuntu 使用 `python3`。`login-stdin` 接收标准输入 JSON，字段为 `username`、`password`、`service`；运营商值为 `0` 校园网、`1` 移动、`2` 联通、`3` 电信。使用原账号工具安全传入凭据，避免把密码写进命令参数或公开日志。

v0.3.1 可从“本机隧道 → 恢复物理网络后登录校园网”填写账号、密码与运营商并登录。管理员先将经核验的脚本放入面板数据目录 `netlogin.py`，或在启动环境设置 `SNA_NETLOGIN_SCRIPT` 为绝对路径。使用面板自身 Python 运行；新认证 AES 需脚本支持的 cryptography、Crypto 或 openssl（桌面完整包已包含 cryptography）。

密码只经本次 HTTP 请求与子进程标准输入传递，不写到命令行、配置或日志，提交后清空输入框。登录前要求隧道全部明确停止、当前用户代理和 PAC 关闭，并由操作者确认没有其他 VPN、透明代理或共享出口。状态探测失败或过渡中会拒绝认证；Ubuntu 无 GNOME 用户会话、代理状态不能确认时不支持从面板登录，应从桌面用户会话启动或依据原脚本流程操作。

认证后自动调用只读 `current-status --json`，仅展示当前账号、运营商、IP 和在线状态，不返回原始认证会话或设备清单。脚本“已在线”可能是其他账号在线，界面会区分“请求已完成”与“输入账号已核对”。公网是否可用仍须查看连接概览的真实 HTTPS 检测。“查询当前校园网状态”只读，不登录、不下线。

面板不会自动注销其他账号，也不会恢复此前被禁用的 timer、cron 或双方互相重启网络的旧守护程序。账号自动登录与网络共享恢复是两个独立步骤。
